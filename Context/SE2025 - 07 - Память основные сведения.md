## Область применения

Данный материал предназначен для студентов, изучающих основы системного программирования и язык C. Он охватывает фундаментальные вопросы организации компьютерной памяти: от физической иерархии устройств до логического управления адресным пространством процесса в современных операционных системах. Предварительные знания включают общее представление об архитектуре фон Неймана (John von Neumann, 1945) и базовый синтаксис языка C.

## Контекст и мотивация

Программы пишутся для обработки данных, которые необходимо где-то хранить. Выбор способа хранения напрямую влияет на производительность системы. Например, аккуратная оптимизация использования кэша может ускорить выполнение программы в 10–20 раз. Понимание того, как данные располагаются в памяти («под капотом»), позволяет писать надежный и эффективный код, избегая «магических» ошибок.

История организации памяти начинается с самых ранних компьютеров. Архитектура фон Неймана (1945) впервые предложила хранить программы и данные в одной памяти. EDVAC (Electronic Discrete Variable Automatic Computer), завершенный в 1949 году, был первым компьютером, реализовавшим эту концепцию. Виртуальная память впервые появилась в компьютере Atlas (University of Manchester, Ferranti, 1962), который использовал страничную организацию памяти и был способен «расширять» доступную память за счет медленного барабанного накопителя.

## Термины и обозначения

- Байт — минимальная адресуемая единица памяти.
- Адрес — уникальный номер ячейки в сплошном массиве памяти.
- Указатель — переменная, хранящая адрес другой ячейки памяти.
- Смещение (Offset) — разность между двумя адресами.
- L-value — выражение, имеющее размещение в памяти (может стоять слева от присваивания).
- R-value — чистое значение, результат вычисления (не имеет собственного адреса в контексте операции).
- Выравнивание (Alignment) — размещение данных по адресам, кратным размеру машинного слова, для ускорения доступа.
- Page Fault — прерывание, возникающее при обращении к странице, отсутствующей в физической памяти.
- TLB (Translation Lookaside Buffer) — кэш таблицы страниц для ускорения преобразования адресов.

## Хранение данных как абстракция

Память в системном программировании рассматривается не как физическое устройство, а как абстракция способа использования ресурсов. Разные задачи требуют разных типов хранилищ: для промежуточных результатов арифметики нужны регистры, для локальных переменных — стек, а для долгого хранения — персистентные носители.

Программы работают только с числами, даже если реальные объекты (текст, изображения) ими не являются. Каждое значение должно иметь свое размещение — непрерывный диапазон в памяти, характеризующийся началом и длиной.

```c
#include <stdio.h>

int main(void) {
    // Демонстрация размещения данных в памяти
    int x = 42;
    int y = 100;
    double z = 3.14;
    
    printf("Значения:\n");
    printf("x = %d\n", x);
    printf("y = %d\n", y);
    printf("z = %.2f\n\n", z);
    
    printf("Адреса (размещение в памяти):\n");
    printf("&x = %p (размер: %zu байт)\n", (void*)&x, sizeof(x));
    printf("&y = %p (размер: %zu байт)\n", (void*)&y, sizeof(y));
    printf("&z = %p (размер: %zu байт)\n", (void*)&z, sizeof(z));
    
    // Разность адресов = смещение
    printf("\nСмещение между x и y: %ld байт\n", 
           (char*)&y - (char*)&x);
    
    return 0;
}
```

## Иерархия классов памяти

Существует экспоненциальный разрыв между объемом и скоростью доступа к разным уровням памяти. Иерархия строится сверху вниз: от самых быстрых и дорогих к медленным и дешевым.

1. **Регистры процессора** — сверхбыстрая память объемом в сотни байт (наносекундный доступ, ~0.5 нс). Современные процессоры x86-64 имеют 16 регистров общего назначения по 64 бита.

2. **Кэш (L1, L2, L3)** — статическая память (SRAM) на кристалле или рядом с ним, объемом от килобайт до мегабайт. Кэш-память впервые появилась в IBM System/360 Model 85 (1968). Современная иерархия:
   - L1: ~32 КБ на ядро, ~1-2 нс
   - L2: ~256 КБ на ядро, ~3-10 нс
   - L3: несколько МБ (разделяемый), ~10-20 нс

3. **Основная память (RAM)** — динамическая память (DRAM) объемом в гигабайты (50-100 наносекунд на доступ). DRAM изобретена Робертом Деннардом (Robert Dennard) в IBM в 1966 году, патент выдан в 1968. DRAM хранит данные в конденсаторах и требует периодического обновления (refresh).

4. **Вторичное хранилище** — энергонезависимые диски:
   - HDD (жесткие диски): ~5-10 мс
   - SSD (твердотельные): ~0.1 мс

5. **Третичное хранилище** — магнитные ленты и оптические диски для долгосрочного архивирования (секунды-минуты доступа).

```c
#include <stdio.h>
#include <time.h>

// Демонстрация эффекта кэша
void cache_demo(void) {
    const int SIZE = 10000000;
    int array[SIZE];
    
    // Инициализация
    for (int i = 0; i < SIZE; i++) {
        array[i] = i;
    }
    
    // Последовательный доступ (хорошо для кэша)
    clock_t start = clock();
    long sum1 = 0;
    for (int i = 0; i < SIZE; i++) {
        sum1 += array[i];
    }
    clock_t end = clock();
    double time1 = (double)(end - start) / CLOCKS_PER_SEC;
    
    // Случайный доступ (плохо для кэша)
    start = clock();
    long sum2 = 0;
    for (int i = 0; i < SIZE; i += 64) {  // Прыжки по 64 элемента
        sum2 += array[i];
    }
    end = clock();
    double time2 = (double)(end - start) / CLOCKS_PER_SEC;
    
    printf("Последовательный доступ: %.6f сек\n", time1);
    printf("С пропусками (64): %.6f сек\n", time2);
}

int main(void) {
    cache_demo();
    return 0;
}
```

## Принцип локальности обращений

Работа эффективных систем основана на эмпирическом правиле: большинство запросов к памяти имеют неравномерный характер. Выделяют два вида локальности:

- **Временная локальность** (Temporal locality) — если данные понадобились сейчас, велика вероятность, что они понадобятся снова в ближайшее время. Пример: переменная счетчика в цикле.

- **Пространственная локальность** (Spatial locality) — если программа обратилась к адресу X, скорее всего, она скоро обратится к адресам рядом (X+1, X+2). Пример: последовательный обход массива.

Процессор использует этот принцип, подгружая данные из медленной оперативной памяти в быстрый кэш целыми блоками (cache lines, обычно 64 байта). Эти принципы были впервые сформулированы Питером Деннингом (Peter Denning) в его работе о рабочих наборах (working sets) в 1968 году.

```c
#include <stdio.h>
#include <time.h>

#define SIZE 1000
#define ITERATIONS 10000

// Демонстрация временной локальности
void temporal_locality_demo(void) {
    int counter = 0;
    
    clock_t start = clock();
    // Многократный доступ к одной переменной
    for (int i = 0; i < ITERATIONS * 1000; i++) {
        counter++;  // Временная локальность: counter в кэше
    }
    clock_t end = clock();
    
    printf("Временная локальность: %.6f сек, counter = %d\n",
           (double)(end - start) / CLOCKS_PER_SEC, counter);
}

// Демонстрация пространственной локальности
void spatial_locality_demo(void) {
    int array[SIZE];
    
    // Последовательный доступ (пространственная локальность)
    clock_t start = clock();
    for (int iter = 0; iter < ITERATIONS; iter++) {
        for (int i = 0; i < SIZE; i++) {
            array[i] = i;  // Соседние элементы в одной cache line
        }
    }
    clock_t end = clock();
    
    printf("Пространственная локальность: %.6f сек\n",
           (double)(end - start) / CLOCKS_PER_SEC);
}

int main(void) {
    temporal_locality_demo();
    spatial_locality_demo();
    return 0;
}
```

## Понятие типа данных в языке C

В языке C тип данных определяет две вещи: объем занимаемой памяти (размещение) и правила выполнения операций с этими байтами. Например, операции сложения для int и float реализуются разными машинными инструкциями, так как форматы представления целых и вещественных чисел принципиально различаются.

При работе с простыми типами важно учитывать:

- **Размер** — int и long могут иметь разную разрядность на разных платформах. Для переносимости рекомендуется использовать типы из <stdint.h> (введены в C99), такие как int32_t или uint64_t.

- **Порядок байтов (Endianness)** — в архитектурах Little-endian (Intel x86, большинство ARM) младший байт числа хранится по меньшему адресу. Big-endian используется в сетевых протоколах и некоторых процессорах (SPARC, PowerPC, некоторые ARM в big-endian режиме).

- **Знаковость** — signed и unsigned интерпретируют одну и ту же битовую последовательность по-разному при сравнении и делении.

```c
#include <stdio.h>
#include <stdint.h>

int main(void) {
    // Размеры типов
    printf("Размеры базовых типов:\n");
    printf("sizeof(int) = %zu\n", sizeof(int));
    printf("sizeof(long) = %zu\n", sizeof(long));
    printf("sizeof(void*) = %zu\n\n", sizeof(void*));
    
    // Типы фиксированного размера
    printf("Типы фиксированного размера:\n");
    printf("sizeof(int32_t) = %zu\n", sizeof(int32_t));
    printf("sizeof(int64_t) = %zu\n\n", sizeof(int64_t));
    
    // Endianness detection
    uint32_t value = 0x01020304;
    uint8_t *bytes = (uint8_t*)&value;
    
    printf("Endianness на этой системе:\n");
    printf("Значение: 0x%08X\n", value);
    printf("Байты в памяти: %02X %02X %02X %02X\n",
           bytes[0], bytes[1], bytes[2], bytes[3]);
    
    if (bytes[0] == 0x04) {
        printf("Little-endian (Intel, ARM)\n");
    } else {
        printf("Big-endian (SPARC, PowerPC, сеть)\n");
    }
    
    return 0;
}
```

## Составные типы и их размещение

Язык C позволяет конструировать сложные структуры из примитивов.

- **Массивы** — набор одинаковых элементов, лежащих в памяти строго подряд без промежутков. Это позволяет использовать адресную арифметику: p[i] эквивалентно *(p + i).

- **Структуры (struct)** — объединение разных типов данных, которые «таскаются» как единое целое. Поля структуры обычно располагаются в памяти в порядке объявления, но между ними могут быть «дырки» (padding) для выравнивания.

- **Объединения (union)** — позволяют хранить разные типы данных в одном и том же участке памяти. Размер union равен размеру его самого крупного поля.

```c
#include <stdio.h>
#include <stdint.h>

// Структура с padding
struct Example {
    char c;      // 1 байт
    // 3 байта padding
    int i;       // 4 байта
    char d;      // 1 байт
    // 3 байта padding
};

// Объединение
union Data {
    int32_t i;
    float f;
    uint8_t bytes[4];
};

int main(void) {
    // Массив - непрерывная последовательность
    int array[5] = {10, 20, 30, 40, 50};
    
    printf("Массив в памяти:\n");
    for (int i = 0; i < 5; i++) {
        printf("array[%d] = %d, адрес = %p\n",
               i, array[i], (void*)&array[i]);
    }
    
    printf("\nЭквивалентность array[i] и *(array + i):\n");
    printf("array[2] = %d\n", array[2]);
    printf("*(array + 2) = %d\n\n", *(array + 2));
    
    // Структура с padding
    struct Example ex;
    printf("Структура с padding:\n");
    printf("sizeof(struct Example) = %zu байт\n", sizeof(ex));
    printf("Адрес c: %p (смещение 0)\n", (void*)&ex.c);
    printf("Адрес i: %p (смещение %ld)\n", 
           (void*)&ex.i, (char*)&ex.i - (char*)&ex);
    printf("Адрес d: %p (смещение %ld)\n\n",
           (void*)&ex.d, (char*)&ex.d - (char*)&ex);
    
    // Объединение
    union Data data;
    data.i = 0x41424344;  // 'ABCD' в ASCII
    
    printf("Объединение (один участок памяти):\n");
    printf("data.i = 0x%08X\n", data.i);
    printf("data.f = %f (интерпретация как float)\n", data.f);
    printf("Байты: %02X %02X %02X %02X\n",
           data.bytes[0], data.bytes[1], data.bytes[2], data.bytes[3]);
    
    return 0;
}
```

## Выравнивание (Alignment) и битовые поля

Компилятор старается размещать данные по адресам, удобным для процессора (например, 4-байтовое целое по адресу, кратному 4). Это ускоряет чтение данных на многих архитектурах (на SPARC и старых ARM невыровненный доступ вызывает hardware exception), но может привести к неэффективному расходованию памяти. Для плотной упаковки данных (например, в сетевых протоколах) используют директивы вроде #pragma pack(1).

Битовые поля позволяют выделять внутри структуры произвольное количество бит для хранения значений (например, int a:5;). Компилятор упаковывает такие поля в одно машинное слово, избавляя программиста от ручного манипулирования масками и сдвигами.

```c
#include <stdio.h>
#include <stdint.h>

// Битовые поля для экономии памяти
struct Flags {
    unsigned int enabled : 1;   // 1 бит
    unsigned int mode : 3;      // 3 бита (0-7)
    unsigned int priority : 4;  // 4 бита (0-15)
    // Всего 1 байт вместо 3 int
};

// Пример аппаратного регистра (embedded)
struct HardwareRegister {
    uint32_t enable : 1;      // Бит 0
    uint32_t interrupt : 1;   // Бит 1
    uint32_t mode : 2;        // Биты 2-3
    uint32_t reserved : 4;    // Биты 4-7
    uint32_t data : 24;       // Биты 8-31
};

int main(void) {
    printf("Битовые поля:\n");
    printf("sizeof(struct Flags) = %zu байт\n\n", sizeof(struct Flags));
    
    struct Flags flags = {0};
    flags.enabled = 1;
    flags.mode = 5;
    flags.priority = 10;
    
    printf("enabled = %u\n", flags.enabled);
    printf("mode = %u\n", flags.mode);
    printf("priority = %u\n\n", flags.priority);
    
    // Выравнивание
    struct {
        char c;
        int i;
    } unaligned;
    
    printf("Выравнивание:\n");
    printf("Адрес c: %p\n", (void*)&unaligned.c);
    printf("Адрес i: %p (выровнен на границу 4 байт)\n",
           (void*)&unaligned.i);
    printf("Смещение: %ld байт (padding)\n",
           (char*)&unaligned.i - (char*)&unaligned.c);
    
    return 0;
}
```

## Организация адресного пространства процесса

Каждый процесс видит память как единый сплошной массив байтов — виртуальное адресное пространство. Типовая схема размещения (для архитектуры x86-64 Linux) включает:

1. **Код (Text)** — машинные инструкции программы, обычно доступны только для чтения. Начинается с младших адресов.
2. **Глобальные данные** — переменные, существующие всё время жизни программы. Делятся на:
   - .data — инициализированные глобальные переменные
   - .bss (Block Started by Symbol) — неинициализированные глобальные переменные
3. **Куча (Heap)** — растет вверх (к старшим адресам), используется для динамической памяти (malloc).
4. **Свободная область** — пространство между кучей и стеком.
5. **Стек (Stack)** — растет вниз от старших адресов к младшим, используется для управления вызовами функций.

```c
#include <stdio.h>
#include <stdlib.h>

int global_var = 42;         // .data сегмент
int uninitialized_global;    // .bss сегмент

void function(void) {
    int local = 10;          // Стек
    printf("Локальная переменная (стек): %p\n", (void*)&local);
}

int main(void) {
    int *heap_var = malloc(sizeof(int));  // Куча
    *heap_var = 100;
    
    printf("Сегменты памяти процесса:\n\n");
    
    printf("Код (функция main): %p\n", (void*)main);
    printf("Код (функция function): %p\n\n", (void*)function);
    
    printf(".data (инициализированная глобальная): %p\n",
           (void*)&global_var);
    printf(".bss (неинициализированная глобальная): %p\n\n",
           (void*)&uninitialized_global);
    
    printf("Куча (malloc): %p\n\n", (void*)heap_var);
    
    int stack_var = 5;
    printf("Стек (локальная переменная main): %p\n", (void*)&stack_var);
    function();
    
    printf("\nНаправление роста:\n");
    printf("Куча растет ↑ (к старшим адресам)\n");
    printf("Стек растет ↓ (к младшим адресам)\n");
    
    free(heap_var);
    return 0;
}
```

## Стек и автоматическая локация

Стек используется как автоматический аллокатор для локальных переменных. При вызове функции создается кадр стека (stack frame или activation record), содержащий:

- Адрес возврата (куда передать управление после завершения)
- Параметры функции
- Локальные переменные
- Сохраненные значения регистров

После выхода из функции кадр считается освобожденным (указатель стека просто смещается), но данные физически остаются в памяти, пока не будут перезаписаны. Это создает опасность обращения к «висячим» указателям.

```c
#include <stdio.h>

void level_3(void) {
    int c = 30;
    printf("  level_3: c = %d, адрес = %p\n", c, (void*)&c);
}

void level_2(void) {
    int b = 20;
    printf(" level_2: b = %d, адрес = %p\n", b, (void*)&b);
    level_3();
    printf(" level_2: возврат из level_3\n");
}

void level_1(void) {
    int a = 10;
    printf("level_1: a = %d, адрес = %p\n", a, (void*)&a);
    level_2();
    printf("level_1: возврат из level_2\n");
}

// Опасность: возврат адреса локальной переменной
int *dangerous_function(void) {
    int local = 42;
    return &local;  // ОШИБКА! local будет уничтожен
}

int main(void) {
    printf("Демонстрация stack frames:\n\n");
    level_1();
    
    printf("\n\nОпасность висячих указателей:\n");
    int *ptr = dangerous_function();
    printf("Адрес: %p\n", (void*)ptr);
    printf("Значение: %d (может быть мусор!)\n", *ptr);
    
    return 0;
}
```

## Куча и динамическое управление

Куча (heap) предоставляет механизм выделения памяти произвольного размера во время выполнения программы. В отличие от стека, память в куче остается выделенной до явного освобождения программистом. Первая реализация malloc появилась в Unix в начале 1970-х годов. Современная реализация dlmalloc (Doug Lea malloc) была создана Дугом Ли (Doug Lea) и стала основой для многих аллокаторов памяти.

Основные функции управления динамической памятью:
- malloc(size) — выделяет size байт
- calloc(n, size) — выделяет n элементов по size байт и обнуляет память
- realloc(ptr, new_size) — изменяет размер выделенного блока
- free(ptr) — освобождает память

```c
#include <stdio.h>
#include <stdlib.h>
#include <string.h>

int main(void) {
    // malloc - выделение памяти
    int *array = malloc(5 * sizeof(int));
    if (array == NULL) {
        fprintf(stderr, "Ошибка выделения памяти\n");
        return 1;
    }
    
    printf("malloc: выделено 5 int (%zu байт)\n", 5 * sizeof(int));
    printf("Адрес: %p\n\n", (void*)array);
    
    // Инициализация
    for (int i = 0; i < 5; i++) {
        array[i] = i * 10;
    }
    
    printf("Значения: ");
    for (int i = 0; i < 5; i++) {
        printf("%d ", array[i]);
    }
    printf("\n\n");
    
    // realloc - изменение размера
    int *bigger_array = realloc(array, 10 * sizeof(int));
    if (bigger_array == NULL) {
        fprintf(stderr, "Ошибка realloc\n");
        free(array);
        return 1;
    }
    array = bigger_array;
    
    printf("realloc: размер увеличен до 10 int\n");
    printf("Новый адрес: %p (может измениться!)\n\n", (void*)array);
    
    // calloc - выделение с обнулением
    int *zeros = calloc(5, sizeof(int));
    if (zeros == NULL) {
        fprintf(stderr, "Ошибка calloc\n");
        free(array);
        return 1;
    }
    
    printf("calloc: выделено и обнулено 5 int\n");
    printf("Значения: ");
    for (int i = 0; i < 5; i++) {
        printf("%d ", zeros[i]);  // Все нули
    }
    printf("\n\n");
    
    // Освобождение памяти
    free(array);
    free(zeros);
    printf("Память освобождена\n");
    
    // Типичная ошибка: double free
    // free(array);  // ОШИБКА! Уже освобождено
    
    // Типичная ошибка: use after free
    // array[0] = 100;  // ОШИБКА! Память освобождена
    
    return 0;
}
```

## Виртуальная память и страничная организация

Виртуальная память позволяет каждому процессу работать с собственным изолированным адресным пространством, даже если физической RAM недостаточно. Концепция виртуальной памяти была реализована впервые в компьютере Atlas (University of Manchester, 1962) под руководством Тома Килбурна (Tom Kilburn).

Пространство разбивается на страницы (обычно по 4096 байт = 4 КБ). Если программа обращается к странице, которой нет в RAM, возникает прерывание (page fault), и ОС подгружает данные с диска.

Преимущества виртуальной памяти:
- Изоляция процессов (защита памяти)
- Возможность выполнять программы больше, чем физическая RAM
- Упрощение управления памятью (каждый процесс видит непрерывное пространство)
- Разделение памяти между процессами (shared memory)

```c
#include <stdio.h>
#include <stdlib.h>
#include <unistd.h>

int main(void) {
    printf("Виртуальная память:\n\n");
    
    // Размер страницы в системе
    long page_size = sysconf(_SC_PAGESIZE);
    printf("Размер страницы: %ld байт (%ld КБ)\n\n",
           page_size, page_size / 1024);
    
    // Выделение памяти
    size_t size = 1024 * 1024;  // 1 МБ
    char *memory = malloc(size);
    if (memory == NULL) {
        fprintf(stderr, "Ошибка malloc\n");
        return 1;
    }
    
    printf("Выделено %zu байт (%zu МБ)\n", size, size / (1024 * 1024));
    printf("Виртуальный адрес: %p\n\n", (void*)memory);
    
    // Доступ к памяти (может вызвать page fault)
    printf("Запись в память (может вызвать page faults)...\n");
    for (size_t i = 0; i < size; i += page_size) {
        memory[i] = (char)i;  // Первый доступ к странице
    }
    printf("Запись завершена\n\n");
    
    printf("Виртуальные адреса:\n");
    printf("- Одинаковы для разных запусков программы\n");
    printf("- Изолированы между процессами\n");
    printf("- Преобразуются в физические через MMU\n");
    
    free(memory);
    return 0;
}
```

## Преобразование адресов (MMU и TLB)

Для каждого обращения к памяти виртуальный адрес должен быть пересчитан в физический. Этим занимается аппаратный модуль MMU (Memory Management Unit). Концепция MMU появилась в 1960-х годах вместе с виртуальной памятью. Для ускорения процесса используется TLB (Translation Lookaside Buffer) — специальный кэш, хранящий последние соответствия страниц.

Процесс преобразования адреса:
1. Виртуальный адрес делится на номер страницы и смещение внутри страницы
2. MMU проверяет TLB (кэш таблицы страниц)
3. Если попадание (TLB hit) — получаем физический адрес сразу (~1-2 такта)
4. Если промах (TLB miss) — обращение к таблице страниц в памяти (~100+ тактов)
5. Если страницы нет в RAM (page fault) — загрузка с диска (миллионы тактов)

```c
#include <stdio.h>

// Демонстрация концепции виртуальных адресов
int global = 100;

void function1(void) {
    static int static_var = 200;
    int local1 = 10;
    
    printf("function1:\n");
    printf("  Локальная (стек): %p\n", (void*)&local1);
    printf("  Static: %p\n", (void*)&static_var);
}

void function2(void) {
    int local2 = 20;
    
    printf("function2:\n");
    printf("  Локальная (стек): %p\n", (void*)&local2);
}

int main(void) {
    int local_main = 5;
    int *heap = (int*)malloc(sizeof(int));
    *heap = 42;
    
    printf("Виртуальные адреса процесса:\n\n");
    
    printf("Код:\n");
    printf("  main: %p\n", (void*)main);
    printf("  function1: %p\n\n", (void*)function1);
    
    printf("Данные:\n");
    printf("  Глобальная: %p\n\n", (void*)&global);
    
    printf("Куча:\n");
    printf("  malloc: %p\n\n", (void*)heap);
    
    printf("Стек:\n");
    printf("  main локальная: %p\n", (void*)&local_main);
    function1();
    function2();
    
    printf("\nЗамечание:\n");
    printf("Все адреса виртуальные.\n");
    printf("MMU преобразует их в физические прозрачно для программы.\n");
    printf("TLB кэширует преобразования для ускорения.\n");
    
    free(heap);
    return 0;
}
```

## Стратегии замены страниц и политики кэширования

При нехватке места в физической памяти для новой страницы ОС должна выбрать «жертву» для выгрузки на диск. Принцип Белади (László Bélády, 1966) гласит, что наиболее эффективно отбрасывать ту информацию, которая не понадобится в будущем дольше всего. Поскольку предсказать будущее невозможно, используются эвристики:

- **LRU (Least Recently Used)** — вытеснение давно не использовавшихся страниц. Основан на принципе временной локальности.
- **FIFO (First-In-First-Out)** — вытеснение самых старых страниц.
- **Clock (Second Chance)** — улучшенный FIFO с битом обращения.
- **MRU (Most Recently Used)** — редко используется, подходит для специфических паттернов доступа.

На уровне процессора управление кэшем (L1–L3) опирается на политики инклюзивности:
- **Inclusive** — данные в L1 обязательно есть в L2 и L3 (Intel до Skylake)
- **Exclusive** — данные только в одном уровне (AMD)
- **NINE (Non-Inclusive Non-Exclusive)** — гибридный подход (Intel с Skylake)

## Динамическое управление памятью: malloc и free

Для выделения памяти в куче используются функции стандартной библиотеки <stdlib.h>. Функция malloc принимает размер в байтах и возвращает указатель; если памяти нет, она возвращает NULL. Для выделения под массив из миллиона целых чисел следует использовать:

```c
int *p = malloc(1000000 * sizeof(int));
if (p == NULL) {
    // Обработка ошибки
}
```

Функция calloc отличается тем, что обнуляет все выделенные биты, а realloc позволяет изменить размер уже выделенного блока, потенциально переместив его на новый адрес. Важно помнить: память, выделенная программистом, должна быть возвращена системе через free, иначе возникнет утечка (memory leak), хотя при завершении процесса современная ОС заберет все ресурсы принудительно.

Типичные ошибки:
- **Memory leak** — потеря указателя на выделенную память без free
- **Double free** — повторное освобождение уже освобожденной памяти
- **Use after free** — использование памяти после её освобождения

Для поиска ошибок используется инструмент Valgrind, созданный Джулианом Сьюардом (Julian Seward) в 2000 году.

```c
#include <stdio.h>
#include <stdlib.h>
#include <string.h>

// Демонстрация типичных ошибок (закомментировано!)

void memory_leak_example(void) {
    int *data = malloc(100 * sizeof(int));
    // Забыли free(data) - утечка памяти!
    // При многократных вызовах память исчерпается
    free(data);  // Правильно
}

void double_free_example(void) {
    int *data = malloc(10 * sizeof(int));
    free(data);
    // free(data);  // ОШИБКА! Double free
}

void use_after_free_example(void) {
    int *data = malloc(10 * sizeof(int));
    data[0] = 42;
    free(data);
    // int x = data[0];  // ОШИБКА! Use after free
}

int main(void) {
    printf("Примеры правильного использования malloc/free:\n\n");
    
    // 1. Проверка на NULL
    int *array = malloc(1000 * sizeof(int));
    if (array == NULL) {
        fprintf(stderr, "Ошибка: не удалось выделить память\n");
        return 1;
    }
    printf("✓ Память выделена и проверена на NULL\n");
    
    // 2. Инициализация
    for (int i = 0; i < 1000; i++) {
        array[i] = i;
    }
    printf("✓ Память инициализирована\n");
    
    // 3. Использование
    printf("  array[500] = %d\n", array[500]);
    
    // 4. Освобождение
    free(array);
    printf("✓ Память освобождена\n\n");
    
    // 5. Обнуление указателя после free (хорошая практика)
    array = NULL;
    printf("✓ Указатель обнулен после free\n\n");
    
    printf("Для поиска ошибок используйте:\n");
    printf("  valgrind ./program\n");
    
    return 0;
}
```

## Порядок байтов в памяти (Endianness)

При хранении многобайтовых чисел (например, int32_t) принципиально важен порядок их расположения. В архитектурах Little-endian (Intel x86/x64, большинство ARM) младший байт числа записывается по меньшему адресу. Например, число 0x11223344 в памяти Little-endian будет начинаться с байта 0x44.

В Big-endian (SPARC, PowerPC, некоторые ARM, сетевые протоколы) старший байт записывается первым. Термины «Big-endian» и «Little-endian» придумал Дэнни Коэн (Danny Cohen) в своей статье «On Holy Wars and a Plea for Peace» (1980), сославшись на «Путешествия Гулливера» Джонатана Свифта.

Это различие становится критичным при передаче данных по сети (сетевой порядок — big-endian по стандарту) или чтении форматов файлов (например, JPEG), где может использоваться противоположный порядок байтов. В языке C стандарт гарантирует корректность чтения числа самой программой, но программист должен учитывать Endianness при побайтовом разборе структур.

```c
#include <stdio.h>
#include <stdint.h>
#include <arpa/inet.h>  // для htonl, ntohl

void print_bytes(void *ptr, size_t size) {
    uint8_t *bytes = (uint8_t*)ptr;
    for (size_t i = 0; i < size; i++) {
        printf("%02X ", bytes[i]);
    }
    printf("\n");
}

int main(void) {
    uint32_t value = 0x11223344;
    
    printf("Endianness demonstration:\n\n");
    printf("Значение: 0x%08X\n", value);
    printf("Байты в памяти: ");
    print_bytes(&value, sizeof(value));
    
    uint8_t *bytes = (uint8_t*)&value;
    if (bytes[0] == 0x44) {
        printf("Система: Little-endian (Intel, ARM)\n");
        printf("Порядок: [44] [33] [22] [11] (младший первым)\n\n");
    } else {
        printf("Система: Big-endian (SPARC, PowerPC, сеть)\n");
        printf("Порядок: [11] [22] [33] [44] (старший первым)\n\n");
    }
    
    // Конвертация для сетевых протоколов
    printf("Сетевой порядок байтов (всегда Big-endian):\n");
    uint32_t network_order = htonl(value);  // host to network long
    printf("После htonl: 0x%08X\n", network_order);
    printf("Байты: ");
    print_bytes(&network_order, sizeof(network_order));
    
    uint32_t back = ntohl(network_order);  // network to host long
    printf("\nПосле ntohl: 0x%08X (обратно)\n\n", back);
    
    printf("Функции для конвертации:\n");
    printf("  htons/ntohs - для 16-бит (short)\n");
    printf("  htonl/ntohl - для 32-бит (long)\n");
    
    return 0;
}
```

## Типовые ошибки и неверные интерпретации

1. **Утечки памяти (Memory Leaks)**: Возникают при потере указателя на выделенную через malloc область без вызова free. Инструмент Valgrind (Julian Seward, 2000) позволяет обнаруживать такие ситуации, анализируя работу программы в реальном времени.

2. **Переполнение буфера (Buffer Overflow)**: Попытка записи за пределы выделенного массива, например, обращение к x[10] в массиве из 10 элементов. Это ведет к повреждению соседних данных или краху программы. Знаменитый Morris Worm (1988) эксплуатировал buffer overflow.

3. **Использование неинициализированных указателей**: Создание `int *y` без присвоения ему адреса и последующая попытка записи `*y = 13` приведет к непредсказуемому поведению, так как указатель содержит «мусорный» адрес.

4. **Segmentation Fault**: Ошибка, возникающая, когда процесс пытается обратиться к странице памяти, доступ к которой ему запрещен или которая не отображена в его адресное пространство.

5. **Путаница со строками**: Строка в C — это массив байтов, заканчивающийся нулем (\0). Если забыть про этот символ при копировании, функции вроде printf будут читать «мусор» из памяти до тех пор, пока случайно не встретят нулевой байт.

## Математические основы

В основе организации памяти лежат следующие формальные принципы и вычисления:

- **Двоичная система счисления и разрядность**: Компьютер хранит данные в битах (0 или 1), где 8 бит образуют 1 байт. Значение в двоичной системе вычисляется как сумма степеней двойки для каждой позиции, где установлен бит: V = Σᵢ bᵢ × 2ⁱ, где bᵢ ∈ {0, 1}.

- **Адресация и объем памяти**: Объем адресуемого пространства определяется разрядностью указателя. Для 32-битной архитектуры количество уникальных адресов составляет 2³² = 4,294,967,296, что соответствует примерно 4 миллиардам ячеек (4 ГБ). Для 64-битной: 2⁶⁴ ≈ 16 эксабайт (теоретически, на практике используется 48 бит).

- **Смещение (Offset)**: Разность между двумя адресами в памяти, определяющая расстояние между ячейками в байтах: offset = addr₂ - addr₁.

- **Адресная арифметика**: При сложении указателя типа T* с целым числом n смещение в байтах вычисляется как: offset = n × sizeof(T).

- **Асимптотическая сложность (Big O)**: Эффективность работы с данными в памяти оценивается через количество операций. Линейный поиск в массиве имеет сложность O(n), в то время как бинарный поиск в отсортированном массиве — O(log n).

- **Выравнивание (Alignment)**: Размещение данных по адресам, кратным степени двойки (обычно размеру машинного слова), для оптимизации тактов чтения процессором: addr mod alignof(T) = 0.

- **Размер структуры**: sizeof(struct) = Σ sizeof(fieldᵢ) + padding, где padding выбирается для выравнивания.

- **TLB эффективность**: Вероятность попадания в TLB (hit rate) критична для производительности. TLB miss стоит ~100 тактов, TLB hit ~1-2 такта.

## Вопросы для собеседования

1. **В чем различие между L-value и R-value в языке C?**
   L-value — это выражение, имеющее размещение в памяти (адрес), которому можно присвоить значение. R-value — это чистое значение результата вычисления, не имеющее собственного адреса в контексте операции.

2. **Когда и где впервые была реализована виртуальная память?**
   В компьютере Atlas (University of Manchester, Ferranti, 1962) под руководством Тома Килбурна (Tom Kilburn).

3. **Кто изобрел DRAM и когда?**
   Роберт Деннард (Robert Dennard) в IBM, патент выдан в 1968 году.

4. **Когда появилась первая кэш-память?**
   В компьютере IBM System/360 Model 85 (1968).

5. **Кто сформулировал принцип локальности?**
   Питер Деннинг (Peter Denning) в работе о рабочих наборах (working sets) в 1968 году.

6. **Кто создал Valgrind и когда?**
   Джулиан Сьюард (Julian Seward) в 2000 году.

7. **Откуда взялись термины Little-endian и Big-endian?**
   Дэнни Коэн (Danny Cohen) придумал их в статье "On Holy Wars and a Plea for Peace" (1980), сославшись на «Путешествия Гулливера».

8. **Как работает стек вызовов (stack frame)?**
   При вызове функции создается кадр стека, содержащий адрес возврата, параметры и локальные переменные. После выхода из функции память кадра считается свободной.

9. **Чем отличается куча (heap) от стека?**
   Стек используется для автоматической локации данных с фиксированным временем жизни, а куча — для динамического распределения памяти произвольного размера, управляемого программистом вручную.

10. **Что такое утечка памяти (memory leak) и как ее обнаружить?**
    Утечка возникает, когда выделенная через malloc память не возвращается системе через free. Для поиска таких ошибок используется инструмент valgrind.

11. **Объясните принцип локальности обращений.**
    Большинство программ обращаются к памяти неравномерно, концентрируясь на данных, которые использовались недавно (временная локальность), или на адресах, расположенных рядом (пространственная локальность).

12. **Что такое Little-endian и Big-endian?**
    Это порядок байтов в многобайтовых числах. В Little-endian (архитектуры Intel x86, ARM) младший байт хранится по меньшему адресу, в Big-endian (SPARC, PowerPC, сеть) — наоборот.

13. **Зачем нужен механизм виртуальной памяти?**
    Он позволяет изолировать процессы друг от друга, предоставляя каждому непрерывное адресное пространство, даже если физическая RAM фрагментирована или её объем меньше требуемого.

14. **Какова роль модуля MMU в системе?**
    Memory Management Unit — это аппаратный блок, выполняющий преобразование виртуальных адресов программы в физические адреса оперативной памяти.

15. **Что происходит при возникновении «прерывания страницы» (page fault)?**
    ОС приостанавливает процесс, подгружает недостающую страницу с диска в RAM, обновляет таблицу страниц и дает команду на повторное выполнение инструкции.

16. **Для чего используется ключевое слово volatile в C?**
    Оно сообщает компилятору, что значение переменной может измениться неожиданно (аппаратно или другим потоком), и запрещает оптимизировать обращения к ней.

17. **В чем заключается риск переполнения буфера (buffer overflow)?**
    Запись данных за пределы выделенного массива приводит к порче соседних данных в памяти, что может вызвать крах программы или уязвимость в безопасности (Morris Worm, 1988).

18. **Что такое TLB и зачем он нужен?**
    Translation Lookaside Buffer — кэш таблицы страниц, ускоряющий преобразование виртуальных адресов в физические (с ~100 тактов до 1-2 тактов при попадании).

19. **Что такое принцип Белади?**
    László Bélády (1966) сформулировал оптимальный алгоритм замены страниц: выгружать ту страницу, которая не понадобится дольше всего. На практике невозможен (требует знания будущего).

20. **Какие типичные размеры имеют страница памяти и cache line?**
    Страница памяти = 4 КБ (4096 байт), cache line = 64 байта.

## Итоги

- Память в системном программировании является абстракцией способа использования вычислительных ресурсов.
- История: архитектура фон Неймана (1945), EDVAC (1949), виртуальная память Atlas (1962), DRAM (Dennard, 1968), кэш (IBM 1968).
- Иерархия памяти строится на компромиссе между скоростью доступа (регистры, кэш) и стоимостью хранения больших объемов данных (RAM, диски).
- Эффективность программ напрямую зависит от соблюдения принципа локальности (Denning, 1968), что позволяет процессору чаще использовать быстрый кэш.
- Типы данных в языке C определяют размер занимаемой памяти и набор допустимых машинных инструкций для обработки этих байтов.
- Виртуальное адресное пространство процесса делится на сегменты: код (read-only), глобальные данные, куча (растет вверх) и стек (растет вниз).
- Управление динамической памятью через malloc и free требует от программиста ответственности за предотвращение утечек и обращений по некорректным адресам.
- Valgrind (Seward, 2000) — основной инструмент поиска ошибок работы с памятью.
- Виртуальная память обеспечивает многозадачность, позволяя ОС динамически подгружать нужные фрагменты кода и данных с помощью страничной организации.
- MMU и TLB обеспечивают эффективное преобразование виртуальных адресов в физические.
- Механизм выравнивания данных в памяти ускоряет чтение, но может создавать «дырки» внутри структур.
- Endianness (Cohen, 1980): Little-endian (Intel, ARM) vs Big-endian (сеть, SPARC) критичен при работе с сетевыми протоколами и бинарными форматами.
- Для понимания того, как данные реально располагаются в памяти, необходимо учитывать архитектурные особенности платформы.
