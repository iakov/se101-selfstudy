## Контекст и мотивация

Операционная система выступает посредником между пользователем и аппаратным обеспечением. Без прикладного ПО сама по себе ОС не имеет смысла, так как её задача — создать стабильную и однотипную среду для решения экономических и прикладных задач. Понимание работы ОС критично для системного программиста при отладке и оптимизации ресурсов.

История операционных систем началась с пакетной обработки в 1950-х годах. CTSS (Compatible Time-Sharing System), разработанная в MIT под руководством Фернандо Корбато (Fernando J. Corbató) и запущенная в 1961 году, стала первой ОС с разделением времени (time-sharing), за что Корбато получил премию Тьюринга в 1990 году. Проект Multics (Multiplexed Information and Computing Service, MIT, Bell Labs, GE, 1965-1969) заложил многие концепции современных ОС, хотя и не достиг коммерческого успеха. Разочарование в Multics привело Кена Томпсона и Денниса Ритчи к созданию Unix в Bell Labs (1969-1971) — более простой и эффективной системы, которая стала основой для большинства современных ОС.

## Термины и обозначения

- Операционная система (ОС) — комплекс программ, обеспечивающий независимое от железа выполнение прикладных программ.
- Ядро (Kernel) — центральная часть ОС, предоставляющая приложениям координированный доступ к ресурсам компьютера.
- Процесс (Process) — идентифицируемая абстракция выполнения программы, владеющая ресурсами.
- Нить (Thread) — абстракция последовательного выполнения кода внутри одного процесса.
- Системный вызов (System Call) — специальная операция, через которую программа запрашивает доступ к ресурсам у ядра.
- Демон/Служба (Daemon/Service) — системный процесс, выполняющийся в фоновом режиме для обслуживания нужд системы.
- Контекст выполнения (Execution Context) — состояние процессора (регистры, стек), необходимое для возобновления выполнения процесса.
- Планировщик (Scheduler) — компонент ОС, распределяющий процессорное время между процессами.

## Задачи и функции операционной системы

ОС решает задачи хранения данных и исполнения программ. Она напрямую управляет процессором (временем), памятью и внешним оборудованием. Главным ресурсом, которым распоряжается ОС, является время процессора.

Система предоставляет абстракцию над аппаратными ресурсами через API (Application Programming Interface — интерфейс прикладного программирования). Это позволяет прикладному ПО быть переносимым между компьютерами с разным «железом». Ядро скрывает различия оборудования, выставляя единый интерфейс доступа к файлам и сети.

Основные функции ОС:
1. **Управление процессами** — создание, планирование, синхронизация, завершение
2. **Управление памятью** — виртуальная память, страничная организация, защита
3. **Управление файлами** — файловые системы, права доступа, кэширование
4. **Управление устройствами** — драйверы, прерывания, буферизация
5. **Защита и безопасность** — изоляция процессов, аутентификация, контроль доступа

```c
#include <stdio.h>
#include <unistd.h>
#include <sys/types.h>

int main(void) {
    // Демонстрация базовых системных вызовов
    
    // getpid() - получить ID текущего процесса
    pid_t pid = getpid();
    printf("Process ID (PID): %d\n", pid);
    
    // getppid() - получить ID родительского процесса
    pid_t ppid = getppid();
    printf("Parent Process ID (PPID): %d\n", ppid);
    
    // getuid() - получить ID пользователя
    uid_t uid = getuid();
    printf("User ID (UID): %d\n", uid);
    
    // Текущая рабочая директория
    char cwd[1024];
    if (getcwd(cwd, sizeof(cwd)) != NULL) {
        printf("Current working directory: %s\n", cwd);
    }
    
    return 0;
}

/* Компиляция: gcc -o system_info system_info.c
   Запуск: ./system_info
   
   Каждый вызов (getpid, getuid, getcwd) - это системный вызов,
   который переключает процессор в режим ядра для выполнения.
*/
```

## Классификация видов ОС

Существуют различные критерии деления ОС: по количеству пользователей, задач и сетевым возможностям. Многопользовательские системы обеспечивают защиту данных одного пользователя от другого. Даже в смартфонах ОС фактически многопользовательская, так как каждое приложение может работать под своим виртуальным пользователем для безопасности.

По управлению временем выделяют **системы реального времени (RTOS — Real-Time Operating System)**. Главное их свойство — гарантия времени выполнения системной операции, что критично в авиации, медицине, промышленной автоматике. В отличие от обычных ОС, где курсор может «зависнуть» на время, RTOS обязана отреагировать в рамках заданного кванта времени. Примеры RTOS: VxWorks (используется в Mars rovers NASA), QNX (автомобили), FreeRTOS (embedded системы).

**Многозадачность** бывает двух типов:
- **Кооперативная** (cooperative multitasking) — задачи должны сами «вежливо» передавать управление другим. Использовалась в Mac OS до версии X, Windows 3.x.
- **Вытесняющая** (preemptive multitasking) — процессор и ОС принудительно прерывают выполнение задачи по таймеру. Впервые реализована в Multics, стала стандартом в Unix и современных ОС.

```c
#include <stdio.h>
#include <unistd.h>
#include <sys/time.h>

// Демонстрация вытесняющей многозадачности
// Программа будет прервана ОС для выполнения других процессов

int main(void) {
    struct timeval start, end;
    long seconds, microseconds;
    double elapsed;
    
    printf("Запуск интенсивных вычислений...\n");
    printf("ОС будет вытеснять этот процесс для других задач\n\n");
    
    gettimeofday(&start, NULL);
    
    // Интенсивные вычисления
    long long sum = 0;
    for (long long i = 0; i < 1000000000LL; i++) {
        sum += i;
    }
    
    gettimeofday(&end, NULL);
    
    seconds = end.tv_sec - start.tv_sec;
    microseconds = end.tv_usec - start.tv_usec;
    elapsed = seconds + microseconds * 1e-6;
    
    printf("Результат: %lld\n", sum);
    printf("Время выполнения: %.3f секунд\n", elapsed);
    printf("\nВо время выполнения ОС многократно переключалась\n");
    printf("между этим процессом и другими процессами в системе\n");
    
    return 0;
}
```

## Ядро ОС и его архитектурные типы

Ядро является «самым главным» в ОС и отвечает за критические функции управления ресурсами. Основные архитектурные типы ядер — монолитные и микроядерные.

**Монолитное ядро** — весь код (драйверы, файловые системы, сетевые стеки) работает в едином адресном пространстве в режиме ядра. Преимущества: высокая производительность (нет накладных расходов на переключение контекста). Недостатки: ошибка в драйвере может обрушить всю систему. Примеры: Linux, традиционные Unix, ранние Windows (до NT).

**Микроядерная архитектура** — максимум функций вынесен в отдельные независимые процессы пользовательского пространства. Само ядро отвечает только за планирование, передачу сообщений (IPC) и базовое управление памятью. Преимущества: надежность, безопасность (сбой драйвера не обрушит систему). Недостатки: снижение производительности из-за частых переключений контекста. Примеры:
- **Mach** (Carnegie Mellon University, 1985-1994) — первая успешная микроядерная ОС, стал основой для NeXTSTEP и macOS
- **MINIX** (Andrew Tanenbaum, 1987) — учебная ОС, вдохновила Линуса Торвальдса на создание Linux
- **QNX** (1982) — коммерческая RTOS, используется в автомобилях и медоборудовании
- **L4** (Jochen Liedtke, 1993) — высокопроизводительное микроядро

Хотя микроядра потенциально безопаснее, большинство современных систем (Linux, Windows NT, Android) остаются монолитными или гибридными (Windows NT — гибрид, часть драйверов в ядре для производительности).

## Исполнение программ и форматы файлов

ОС понимает только свои «родные» форматы исполняемых файлов:
- **ELF (Executable and Linkable Format)** — Linux, BSD, Solaris. Стандартизирован в 1999 году как замена устаревшего a.out.
- **PE (Portable Executable)** — Windows (представлен Microsoft в 1993 с Windows NT). Основан на формате COFF (Common Object File Format).
- **Mach-O** — macOS, iOS (от NeXTSTEP)

В заголовке такого файла указано, сколько памяти выделить и с какого адреса начать выполнение кода. Механизм **binfmt_misc** в Linux (появился в ядре 2.1.43, 1997) позволяет запускать даже «неродные» файлы через соответствующие интерпретаторы (например, Windows .exe через Wine, Python скрипты, Java .class).

```c
#include <stdio.h>
#include <stdlib.h>

int main(void) {
    printf("hello, world\n");
    return 0;
}

/*
Жизненный цикл программы:

1. КОМПИЛЯЦИЯ:
   gcc -o hello hello.c
   Создается исполняемый файл в формате ELF (Linux) или PE (Windows)

2. ЗАГРУЗКА (когда вы запускаете ./hello):
   - ОС читает заголовок файла
   - Проверяет формат (ELF magic number: 0x7F 'E' 'L' 'F')
   - Создает новый процесс
   - Выделяет виртуальное адресное пространство
   - Загружает секции кода (.text) и данных (.data, .bss)
   - Загружает динамические библиотеки (например, libc.so)
   - Настраивает таблицу PLT/GOT для динамического связывания
   - Передает управление на точку входа (_start, которая вызывает main)

3. ВЫПОЛНЕНИЕ:
   - Процесс выполняется в режиме пользователя
   - printf() вызывает системный вызов write()
   - Переключение в режим ядра
   - Ядро выполняет запись в stdout
   - Возврат в режим пользователя

4. ЗАВЕРШЕНИЕ:
   - return 0 вызывает exit(0)
   - exit() - системный вызов
   - Ядро освобождает ресурсы процесса
   - Процесс переходит в состояние Zombie
   - Родитель вызывает wait() и читает код завершения
   - Запись о процессе удаляется из таблицы процессов
*/
```

## Процессы и нити

**Процесс** — это «ожившая» программа в памяти, появившаяся концепция в Multics и Unix. Он владеет ресурсами:
- Виртуальное адресное пространство (код, данные, стек, куча)
- Открытые файлы и дескрипторы
- Сетевые соединения
- Переменные окружения
- Идентификаторы (PID, UID, GID)

ОС изолирует процессы друг от друга, чтобы ошибка в одном не обрушила всю систему. Каждый процесс имеет свою таблицу страниц виртуальной памяти.

**Нить (Thread)** — это единица выполнения внутри процесса. Концепция потоков появилась в 1960-х (Multics), но широкое распространение получила в 1990-х (POSIX Threads — pthread, стандартизирован в 1995). У одного процесса может быть много нитей, которые делят между собой все его ресурсы (память, файлы), но имеют собственные стеки и регистры. Это удобно для параллельного выполнения задач.

```c
#include <stdio.h>
#include <pthread.h>
#include <unistd.h>

// Функция, которую будет выполнять поток
void *thread_function(void *arg) {
    int id = *(int*)arg;
    for (int i = 0; i < 3; i++) {
        printf("Thread %d: iteration %d\n", id, i);
        sleep(1);
    }
    return NULL;
}

int main(void) {
    pthread_t thread1, thread2;
    int id1 = 1, id2 = 2;
    
    printf("Main process PID: %d\n", getpid());
    printf("Creating threads...\n\n");
    
    // Создание двух потоков
    pthread_create(&thread1, NULL, thread_function, &id1);
    pthread_create(&thread2, NULL, thread_function, &id2);
    
    // Ожидание завершения потоков
    pthread_join(thread1, NULL);
    pthread_join(thread2, NULL);
    
    printf("\nAll threads completed\n");
    
    return 0;
}

/* Компиляция: gcc -pthread -o threads threads.c
   
   Потоки vs Процессы:
   - Потоки разделяют память процесса (быстрее создаются)
   - Процессы изолированы (безопаснее, но медленнее)
   - Потоки полезны для параллельных вычислений на многоядерных CPU
*/
```

## Механизмы запуска и завершения программ

Запуск программы начинается с выделения адресного пространства под код, данные и начальный стек. ОС загружает необходимые динамические библиотеки и инициализирует глобальные переменные. После подготовки управление передается в «точку входа» (обычно функция `_start`, которая подготавливает окружение и вызывает `main`), и код начинает выполняться.

В Unix механизм создания процессов основан на системных вызовах **fork()** и **exec()**:
- **fork()** — создает точную копию (клон) текущего процесса. Родитель и потомок идентичны, но имеют разные PID.
- **exec()** семейство — заменяет код текущего процесса новой программой из файла.

Этот механизм был разработан в Unix (1970-е) и стал стандартом для POSIX-совместимых систем.

Завершаясь, процесс вызывает системный вызов `exit()`, сигнализирующий о конце работы. Надежная ОС обязана освободить все ресурсы, которые занимал процесс, даже если программист забыл это сделать явно (например, не закрыл файл).

```c
#include <stdio.h>
#include <unistd.h>
#include <sys/types.h>
#include <sys/wait.h>

int main(void) {
    pid_t pid = fork();
    
    if (pid < 0) {
        // Ошибка fork
        fprintf(stderr, "Fork failed\n");
        return 1;
    }
    else if (pid == 0) {
        // Код дочернего процесса
        printf("CHILD:  PID = %d, PPID = %d\n", getpid(), getppid());
        printf("CHILD:  Executing 'ls' command...\n");
        
        // Замена кода процесса на /bin/ls
        execlp("/bin/ls", "ls", "-l", NULL);
        
        // Эта строка выполнится только если exec() завершился с ошибкой
        perror("exec failed");
        return 1;
    }
    else {
        // Код родительского процесса
        printf("PARENT: PID = %d\n", getpid());
        printf("PARENT: Created child with PID = %d\n", pid);
        printf("PARENT: Waiting for child to complete...\n");
        
        // Ожидание завершения дочернего процесса
        int status;
        wait(&status);
        
        printf("PARENT: Child completed with status %d\n", 
               WEXITSTATUS(status));
    }
    
    return 0;
}

/*
Вывод программы:
  PARENT: PID = 1234
  PARENT: Created child with PID = 1235
  PARENT: Waiting for child to complete...
  CHILD:  PID = 1235, PPID = 1234
  CHILD:  Executing 'ls' command...
  [вывод команды ls -l]
  PARENT: Child completed with status 0

Последовательность:
1. fork() создает копию процесса
2. Родитель получает PID ребенка
3. Ребенок получает 0
4. Ребенок вызывает exec(), заменяя свой код на /bin/ls
5. Родитель ждет через wait()
6. После завершения ls, родитель продолжает работу
*/
```

## Типовые ошибки и неверные интерпретации

Самое частое заблуждение — путаница между ядром, семейством ОС и дистрибутивом:
- **Linux** — это только ядро (создано Линусом Торвальдсом в 1991 году)
- **GNU/Linux** — это семейство систем, включающее утилиты проекта GNU (Richard Stallman, FSF) и ядро Linux
- **Дистрибутив** (например, Debian, Ubuntu, Arch, Fedora) — это согласованный набор конкретных версий программ и настроек

Также ошибочно судить об ОС только по графической оболочке (KDE, GNOME, Xfce) или теме оформления. Оболочка — это лишь «картинка», которая не влияет на архитектуру ядра или работу планировщика.

## Механизмы загрузки и «оживления» операционной системы

Процесс запуска ОС (boot process) начинается после того, как аппаратное обеспечение (процессор) инициализирует первые инструкции из ПЗУ:

1. **Power-On Self-Test (POST)** — BIOS/UEFI проверяет оборудование
2. **Bootloader** (GRUB для Linux, Windows Boot Manager) — загружает ядро в память
   - GRUB (Grand Unified Bootloader) — стандартный загрузчик Linux, появился в 1995 (GRUB 2 в 2005)
3. **Kernel initialization** — ядро инициализирует процессор, память, драйверы
4. **Init process (PID 1)** — первая пользовательская программа

Первой программой, которую запускает ядро в пространстве пользователя, является **Init** (процесс с идентификатором PID=1). Варианты:
- **SysV init** — традиционный init из AT&T System V Unix (1980-е)
- **Upstart** — разработан Canonical для Ubuntu (2006)
- **systemd** — современный init, создан Lennart Poettering (Red Hat, 2010), стал стандартом для большинства дистрибутивов Linux
- **launchd** — macOS (2005)
- **wininit.exe** — Windows

Init запускает все остальные фоновые процессы и сервисы. Такие системные процессы, работающие без участия пользователя, называются **демонами** (daemons).

После поднятия сетевых настроек и системных утилит запускается приложение для аутентификации. Только после успешного подтверждения личности пользователя ОС загружает графическую оболочку и приложения из списка автозагрузки.

## Форматы исполняемых файлов и механизмы запуска

ОС не может исполнить произвольный набор байтов; файл должен соответствовать «родному» для системы формату:
- **Windows**: PE (Portable Executable) — представлен в 1993 с Windows NT
- **Linux**: ELF (Executable and Linkable Format) — стандартизирован в 1999, заменил a.out
- **macOS**: Mach-O — от NeXTSTEP

Эти форматы содержат заголовки, в которых указано:
- Magic number (идентификатор формата: ELF = 0x7F 'E' 'L' 'F')
- Архитектура (x86, x86-64, ARM)
- Точка входа (адрес начала выполнения)
- Секции кода (.text), данных (.data, .bss), таблицы символов
- Список необходимых динамических библиотек

Для запуска «неродных» файлов (например, скриптов на Python или приложений Windows в Linux) используется механизм **binfmt_misc** (binary format miscellaneous, добавлен в Linux kernel 2.1.43, 1997). Он позволяет ядру вызвать соответствующий интерпретатор или эмулятор, если заголовок файла совпадает с заданным шаблоном.

Сам процесс порождения новой программы в памяти часто реализуется через механизмы **fork** (создание клона текущего процесса) и **exec** (замена кода текущего процесса кодом из файла).

```c
#include <stdio.h>
#include <unistd.h>
#include <fcntl.h>

// Демонстрация чтения заголовка ELF файла
int main(int argc, char *argv[]) {
    if (argc != 2) {
        fprintf(stderr, "Usage: %s <executable>\n", argv[0]);
        return 1;
    }
    
    int fd = open(argv[1], O_RDONLY);
    if (fd < 0) {
        perror("open");
        return 1;
    }
    
    unsigned char header[16];
    if (read(fd, header, 16) != 16) {
        perror("read");
        close(fd);
        return 1;
    }
    
    printf("Первые 16 байт файла:\n");
    for (int i = 0; i < 16; i++) {
        printf("%02X ", header[i]);
    }
    printf("\n\n");
    
    // Проверка ELF magic number
    if (header[0] == 0x7F && header[1] == 'E' && 
        header[2] == 'L' && header[3] == 'F') {
        printf("Это ELF файл!\n");
        
        if (header[4] == 1) printf("  32-bit\n");
        else if (header[4] == 2) printf("  64-bit\n");
        
        if (header[5] == 1) printf("  Little-endian\n");
        else if (header[5] == 2) printf("  Big-endian\n");
    } else {
        printf("Не ELF файл\n");
    }
    
    close(fd);
    return 0;
}

/* Использование:
   gcc -o check_elf check_elf.c
   ./check_elf /bin/ls
   
   Вывод:
   Первые 16 байт файла:
   7F 45 4C 46 02 01 01 00 00 00 00 00 00 00 00 00
   
   Это ELF файл!
     64-bit
     Little-endian
*/
```

## Состояния процессов и «Зомби»

Процесс в ОС — это не статичный объект, он постоянно меняет свои состояния. Основные состояния (в терминологии Unix/Linux):

- **Running (R)** — процесс выполняется на процессоре в данный момент или готов к выполнению (в очереди планировщика).
- **Sleeping (S/D)** — процесс ожидает ресурса (например, данных с диска) или сигнала:
  - **S (Interruptible sleep)** — прерываемый сон, можно разбудить сигналом
  - **D (Uninterruptible sleep)** — непрерываемый сон, обычно ожидание ввода-вывода (I/O wait)
- **Stopped (T)** — выполнение процесса приостановлено сигналом SIGSTOP или отладчиком.
- **Zombie (Z)** — процесс завершился, но запись о нем все еще хранится в таблице процессов ОС, пока родительский процесс не прочитает его код завершения через `wait()`.

Важной обязанностью ОС является освобождение ресурсов (памяти, открытых файлов) после завершения процесса, даже если программист забыл сделать это явно.

```c
#include <stdio.h>
#include <stdlib.h>
#include <unistd.h>
#include <sys/wait.h>

// Демонстрация состояния Zombie
int main(void) {
    pid_t pid = fork();
    
    if (pid < 0) {
        perror("fork");
        return 1;
    }
    else if (pid == 0) {
        // Дочерний процесс
        printf("CHILD: PID=%d, starting...\n", getpid());
        sleep(2);
        printf("CHILD: Exiting...\n");
        exit(42);  // Код завершения 42
    }
    else {
        // Родительский процесс
        printf("PARENT: Child PID=%d created\n", pid);
        printf("PARENT: Sleeping for 5 seconds...\n");
        printf("PARENT: During this time, child will become ZOMBIE\n");
        printf("PARENT: Run 'ps aux | grep Z' in another terminal to see it\n\n");
        
        sleep(5);
        
        printf("\nPARENT: Now calling wait() to reap zombie\n");
        int status;
        pid_t wpid = wait(&status);
        
        if (WIFEXITED(status)) {
            printf("PARENT: Child %d exited with code %d\n", 
                   wpid, WEXITSTATUS(status));
        }
        
        printf("PARENT: Zombie reaped, no longer in process table\n");
    }
    
    return 0;
}

/*
Жизненный цикл процесса:

  [New] → [Ready] → [Running] → [Terminated]
            ↑  ↓         ↓
         [Blocked] ←────┘
            (I/O wait)

После Terminated, если родитель не вызвал wait():
  [Terminated] → [Zombie] (остается в таблице процессов)

После wait():
  [Zombie] → удаление из таблицы процессов
*/
```

## Взаимодействие процессов (IPC)

В многозадачных системах процессам часто необходимо обмениваться данными, для чего используются механизмы **IPC (Inter-Process Communication)**. Unix предоставил множество механизмов IPC, которые стали стандартом POSIX:

1. **Сигналы (Signals)** — асинхронные уведомления о событиях (SIGINT, SIGTERM, SIGKILL и др.). Появились в ранних Unix (1970-е).

2. **Каналы (Pipes)** — позволяют перенаправлять вывод одной программы на ввод другой. Появились в Unix Version 3 (1973, Doug McIlroy). Пример: `ls | grep txt`

3. **Именованные каналы (Named Pipes/FIFO)** — каналы с именем в файловой системе.

4. **Сокеты (Sockets)** — универсальная абстракция для обмена данными, в том числе по сети. Появились в BSD Unix 4.2 (1983).

5. **Разделяемая память (Shared Memory)** — наиболее быстрый способ, когда два процесса имеют доступ к одному физическому участку памяти. POSIX shared memory стандартизирован в 1990-х.

6. **Очереди сообщений (Message Queues)** — асинхронная передача структурированных сообщений.

7. **Семафоры (Semaphores)** — примитивы синхронизации, изобретены Эдсгером Дейкстрой (Edsger Dijkstra) в 1965 году.

```c
#include <stdio.h>
#include <unistd.h>
#include <string.h>

// Демонстрация Pipes (каналов)
int main(void) {
    int pipefd[2];  // pipefd[0] - чтение, pipefd[1] - запись
    pid_t pid;
    char buffer[100];
    
    // Создание канала
    if (pipe(pipefd) == -1) {
        perror("pipe");
        return 1;
    }
    
    pid = fork();
    
    if (pid < 0) {
        perror("fork");
        return 1;
    }
    else if (pid == 0) {
        // Дочерний процесс - чтение из канала
        close(pipefd[1]);  // Закрываем конец для записи
        
        ssize_t n = read(pipefd[0], buffer, sizeof(buffer));
        buffer[n] = '\0';
        
        printf("CHILD: Received message: \"%s\"\n", buffer);
        
        close(pipefd[0]);
    }
    else {
        // Родительский процесс - запись в канал
        close(pipefd[0]);  // Закрываем конец для чтения
        
        const char *msg = "Hello from parent!";
        printf("PARENT: Sending message: \"%s\"\n", msg);
        
        write(pipefd[1], msg, strlen(msg));
        
        close(pipefd[1]);
        wait(NULL);  // Ждем завершения ребенка
    }
    
    return 0;
}

/*
Pipe в командной строке:
  ls -l | grep txt | wc -l

Это создает три процесса:
  ls -l → пишет в pipe → grep txt → пишет в pipe → wc -l
  
Pipe - это буфер в ядре, соединяющий stdout одного процесса
с stdin другого процесса.
*/
```

## Масштабы разработки и трудоемкость

Современные операционные системы — это колоссальные программные проекты. Ядро Linux за три десятилетия выросло с 176 тысяч строк кода (версия 1.0.0 в 1994 году) до более 30 миллионов строк в версии 6.x (2024 год). При этом более 95% этого объема составляет поддержка различных аппаратных устройств и протоколов (драйверы, файловые системы, сетевые стеки).

Основные вехи Linux:
- **1991**: Линус Торвальдс (Linus Torvalds) анонсирует Linux 0.01 (10,239 строк кода)
- **1994**: Linux 1.0.0 (176,250 строк)
- **2003**: Linux 2.6.0 (~6 млн строк) — введена O(1) планировщик
- **2011**: Linux 3.0 (~15 млн строк)
- **2024**: Linux 6.x (~30 млн строк)

Существуют и экстремально компактные системы:
- **KolibriOS** — 1 МБ на диске, 8 МБ RAM, с графическим интерфейсом
- **MenuetOS** — написана полностью на ассемблере, ~1.44 МБ
- **FreeRTOS** — ядро ~9000 строк кода для embedded систем

Для сравнения, Windows NT (1993) содержала ~4-5 млн строк кода, современные Windows 10/11 — оценочно 50+ млн строк.

## Типовые ошибки и неверные интерпретации

1. **Отождествление Linux с ОС**. Технически Linux — это только ядро (kernel). Полноценная ОС называется GNU/Linux, так как включает системные утилиты и библиотеки проекта GNU (GNU's Not Unix, Richard Stallman, 1983).

2. **Оценка системы по оболочке**. Графическая тема (иконки, шрифты) не определяет архитектуру ядра или планировщика. Например, Windows можно стилизовать под macOS, но она останется системой на ядре NT.

3. **Путаница между дистрибутивом и семейством**. Debian, Ubuntu и Arch — это разные дистрибутивы (наборы программ), принадлежащие одному семейству GNU/Linux.

4. **Игнорирование системных вызовов**. Программисты иногда забывают, что любой ввод-вывод — это тяжелая операция, требующая переключения в режим ядра. Использование `strace` помогает увидеть все системные вызовы и оптимизировать работу с ресурсами.

```c
// Используйте strace для анализа системных вызовов:
// strace ./program
//
// Вывод покажет все вызовы: open(), read(), write(), close(), mmap() и т.д.
```

## Математические и теоретические основы

В основе функционирования современных операционных систем лежит булева логика, используемая для проверки условий при переключении состояний процессов и управлении потоками. Теоретическим фундаментом распределения ресурсов служит классификация уровней безопасности (классы A, B, C по стандарту Orange Book, 1985), определяющая строгость контроля доступа к данным.

**Математическая абстракция линейного адресного пространства** позволяет операционной системе отображать виртуальные адреса программ на физические ячейки памяти, обеспечивая изоляцию процессов. Для процесса с n-битными адресами доступно адресное пространство размером 2^n байт.

**Управление временем в многозадачных системах** опирается на квантование (time slicing), где процессор и ОС принудительно прерывают выполнение задачи для передачи управления следующей в очереди. Типичный квант времени (time quantum) составляет 1-100 миллисекунд.

**Планирование процессов** формализуется через алгоритмы:
- **FIFO (First In, First Out)** — простейший, неэффективен
- **Round Robin** — циклическое выделение квантов времени
- **Priority Scheduling** — приоритетное планирование
- **Multilevel Feedback Queue** — многоуровневые очереди с обратной связью
- **CFS (Completely Fair Scheduler)** — Linux, основан на красно-черных деревьях, O(log n) сложность

**Синхронизация процессов**: Семафор S с операциями P(S) и V(S):
- P(S): while (S ≤ 0) wait; S := S - 1
- V(S): S := S + 1

**Граф ресурсов** (Resource Allocation Graph) используется для обнаружения дедлоков (deadlocks). Цикл в графе указывает на возможность взаимной блокировки.

## Вопросы для подготовки к собеседованию

1. **В чем принципиальное различие между процессом и нитью (thread)?**
   Процесс является изолированной абстракцией выполнения программы и владеет собственными ресурсами (память, файлы), тогда как нити существуют внутри процесса и делят его память и файлы, но имеют собственные стеки и регистры.

2. **Кто и когда создал Unix?**
   Кен Томпсон (Ken Thompson) и Деннис Ритчи (Dennis Ritchie) в Bell Labs, 1969-1971.

3. **Кто создал CTSS и что это было?**
   Фернандо Корбато (Fernando J. Corbató) и команда MIT, 1961. CTSS (Compatible Time-Sharing System) — первая ОС с разделением времени. Корбато получил премию Тьюринга в 1990.

4. **Что такое Multics и его значение?**
   Multiplexed Information and Computing Service (MIT, Bell Labs, GE, 1965-1969). Заложил концепции современных ОС (виртуальная память, файловая система, безопасность), но был сложным. Разочарование в нем привело к созданию Unix.

5. **Кто создал Linux и когда?**
   Линус Торвальдс (Linus Torvalds), анонс 25 августа 1991 года в группе новостей comp.os.minix.

6. **Какова роль процесса с идентификатором PID 1 (Init)?**
   Это первый главный процесс, который порождается ядром и отвечает за запуск всех остальных системных служб и демонов. Варианты: SysV init, systemd, launchd.

7. **Что гарантирует система реального времени (RTOS), в отличие от ОС общего назначения?**
   RTOS гарантирует время выполнения системной операции (детерминированность), что критично для авиации или медицины, тогда как обычные ОС ориентированы на среднюю производительность.

8. **Как работает вытесняющая многозадачность?**
   ОС и аппаратный таймер процессора принудительно останавливают текущую задачу (прерывание по таймеру), не дожидаясь от неё вежливой передачи управления. Впервые реализована в Multics.

9. **Зачем нужны системные вызовы?**
   Это единственный способ для прикладной программы запросить доступ к ресурсам, контролируемым ядром (чтение файла, отправка данных по сети, создание процесса).

10. **В чем разница между форматами ELF и PE?**
    ELF (Executable and Linkable Format) — Linux/Unix, стандартизирован 1999. PE (Portable Executable) — Windows, представлен Microsoft в 1993 с Windows NT. Оба содержат заголовки с инструкциями по размещению кода в памяти.

11. **Что такое процесс-зомби?**
    Это процесс, который завершил выполнение, но запись о нем сохраняется в таблице процессов ОС до тех пор, пока родительский процесс не прочитает его код завершения через wait().

12. **Почему Linux — это не дистрибутив?**
    Технически Linux является только ядром. Дистрибутив (например, Debian, Ubuntu, Fedora) — это согласованный набор системных утилит, библиотек GNU и прикладных программ вокруг ядра Linux.

13. **Каковы особенности микроядерной архитектуры?**
    В такой архитектуре максимум функций (драйверы, файловые системы) вынесены в независимые процессы пользовательского пространства, а ядро отвечает только за планирование и передачу сообщений (IPC). Примеры: Mach, MINIX, QNX, L4.

14. **Какую функцию выполняет механизм binfmt в Linux?**
    Он позволяет ядру автоматически вызывать нужный интерпретатор для запуска «неродных» файлов, основываясь на их заголовках или расширениях. Добавлен в kernel 2.1.43 (1997).

15. **Объясните механизм fork/exec.**
    fork() создает точную копию текущего процесса. exec() заменяет код текущего процесса новой программой из файла. Вместе они образуют стандартный Unix-механизм запуска программ.

16. **Что такое POSIX?**
    Portable Operating System Interface — семейство стандартов IEEE для совместимости Unix-подобных ОС. Определяет API системных вызовов, утилит, threads и т.д.

17. **Перечислите механизмы IPC.**
    Signals, Pipes (1973), Named Pipes/FIFO, Sockets (BSD 1983), Shared Memory, Message Queues, Semaphores (Dijkstra, 1965).

18. **Что такое systemd и когда он появился?**
    Современная система инициализации и управления сервисами для Linux. Создан Lennart Poettering (Red Hat) в 2010 году. Заменил SysV init в большинстве дистрибутивов.

19. **Назовите примеры RTOS.**
    VxWorks (используется в Mars rovers NASA), QNX (автомобили), FreeRTOS (embedded системы), RTEMS.

20. **Кто изобрел семафоры?**
    Эдсгер Дейкстра (Edsger Dijkstra) в 1965 году.

## Итоги и направления для дальнейшего изучения

- Операционная система выступает незаметным, но необходимым посредником между пользователем и «железом».
- История ОС: CTSS (1961) → Multics (1965-1969) → Unix (1969-1971) → Linux (1991) и другие современные системы.
- Главным ресурсом, которым распоряжается ОС в условиях многозадачности, является процессорное время.
- Изоляция адресных пространств необходима для предотвращения порчи данных одного процесса другим.
- Использование API обеспечивает переносимость программ между компьютерами с разной аппаратной начинкой.
- Жизненный цикл любой программы в ОС начинается с процесса Init (PID=1) и заканчивается освобождением ресурсов ядром.
- Механизмы IPC (signals, pipes, sockets, shared memory) обеспечивают взаимодействие процессов.
- Сложность современных ядер ОС достигает десятков миллионов строк кода (Linux: 10k в 1991 → 30M в 2024).
- Форматы исполняемых файлов (ELF, PE, Mach-O) определяют, как ОС загружает программы в память.
- Микроядерная архитектура (Mach, QNX, L4) безопаснее монолитной, но менее производительна.
- Существуют специализированные компактные ОС (KolibriOS, MenuetOS), способные работать при экстремально малых ресурсах.
- RTOS (VxWorks, QNX, FreeRTOS) гарантируют время отклика, критичное для встроенных систем.

## Связанные темы

Развитие навыков системного программирования потребует углубления в следующие области:

- **Архитектура ЭВМ**: Взаимодействие процессора с памятью, прерывания, DMA, режимы работы процессора (user mode vs kernel mode).
- **Иерархия памяти**: Механизмы работы стека и кучи, виртуальная память, страничная организация, MMU, TLB.
- **Планирование процессов**: Алгоритмы FIFO, Round Robin, CFS, приоритеты, реального времени.
- **Синхронизация**: Семафоры, мьютексы, condition variables, проблемы race conditions и deadlocks.
- **Файловые системы**: ext4, NTFS, APFS, FAT32, журналирование, индексные дескрипторы (inodes).
- **Сетевые подсистемы**: Стек TCP/IP, сокеты, драйверы сетевых карт.
- **Безопасность ОС**: Управление доступом (DAC, MAC), SELinux, AppArmor, песочницы (sandboxing).
- **История вычислительной техники**: Эволюция от пакетной обработки к time-sharing к многозадачности к виртуализации.
