## Область применения

Данный материал предназначен для студентов первого курса, изучающих основы программирования и устройство операционных систем. Для освоения темы требуются базовые знания о двоичной системе счисления и представлении данных в памяти ЭВМ. Материал ограничивается рассмотрением файлов как объектов операционной системы и абстракций в языке программирования C.

## Контекст и мотивация

Программисты работают с данными, которые необходимо хранить в целости и сохранности. Файлы являются основным способом организации именованных данных для их последующей многократной интерпретации. Понимание того, как ОС управляет файлами, позволяет писать более эффективный, надежный и кроссплатформенный код.

Концепция файловых систем эволюционировала с самых ранних компьютеров. Первая файловая система появилась в 1956 году на IBM 305 RAMAC — первом компьютере с жестким диском. Multics (1965-1969) ввел иерархическую файловую систему с директориями, которая стала стандартом. Unix (1969-1971, Ken Thompson & Dennis Ritchie) популяризировал концепцию "everything is a file" — устройства, каналы и процессы представляются как файлы. Это унифицировало интерфейс доступа к ресурсам и стало фундаментальным принципом Unix-подобных систем.

## Термины и обозначения

- Файл — именованные данные, подлежащие хранению и обработке.
- Regular files (обычные файлы) — данные, сохраненные на энергонезависимом носителе (диске).
- Special files (специальные файлы) — объекты файловой системы, представляющие устройства или виртуальные источники данных.
- Директория (Directory) — технический термин файловой системы, обозначающий группировку файлов.
- ASCII-Z (ASCIIZ) — формат строки, заканчивающейся нулевым байтом (\0), используемый в C.
- Stream (поток) — абстракция в языке C (FILE*), позволяющая унифицированно работать с различными типами файлов.
- Inode — индексный дескриптор, структура данных, хранящая метаданные файла в Unix-подобных системах.
- Magic number — сигнатурные байты в начале файла, определяющие его формат.

## Понятие файла и его свойства

В широком смысле файл определяется как именованная коллекция данных, рассматриваемая как единое целое. Для пользователя файл — это объект, имеющий имя, формат (расширение) и метаданные, такие как дата создания или права доступа. Операционная система использует файлы для обеспечения целостности данных и структурированного доступа к ним.

Исторически расширение файла (буквы после последней точки) служило для определения его типа и принадлежности. Эта концепция появилась в CP/M (Control Program for Microcomputers, 1974, Gary Kildall) с ограничением 8.3 (8 символов имени, 3 символа расширения), которое было унаследовано MS-DOS и ранними версиями Windows. В современных системах расширение часто является лишь подсказкой, а реальные свойства определяются внутренней структурой данных (magic numbers).

К важным системным свойствам относятся права доступа. Unix (1971) ввел модель прав rwx (read, write, execute) для владельца, группы и остальных — систему, используемую до сих пор.

Файлы также обладают временными метками (timestamps):
- **ctime** (change time) — время изменения метаданных inode
- **mtime** (modification time) — время изменения содержимого
- **atime** (access time) — время последнего доступа

Некоторые форматы (например, JPEG с EXIF, введен в 1995 Japan Electronic Industries Development Association) хранят дату внутри самих данных для сохранения контекста.

```c
#include <stdio.h>
#include <sys/stat.h>
#include <time.h>

// Демонстрация получения метаданных файла
int main(int argc, char *argv[]) {
    if (argc != 2) {
        fprintf(stderr, "Usage: %s <filename>\n", argv[0]);
        return 1;
    }
    
    struct stat file_stat;
    
    if (stat(argv[1], &file_stat) == -1) {
        perror("stat");
        return 1;
    }
    
    printf("Метаданные файла: %s\n\n", argv[1]);
    printf("Размер: %ld байт\n", file_stat.st_size);
    printf("Inode: %lu\n", file_stat.st_ino);
    printf("Права доступа: %o\n", file_stat.st_mode & 0777);
    
    // Временные метки
    printf("\nВременные метки:\n");
    printf("Изменение содержимого: %s", ctime(&file_stat.st_mtime));
    printf("Последний доступ:      %s", ctime(&file_stat.st_atime));
    printf("Изменение метаданных:  %s", ctime(&file_stat.st_ctime));
    
    // Тип файла
    printf("\nТип файла: ");
    if (S_ISREG(file_stat.st_mode)) printf("Обычный файл\n");
    else if (S_ISDIR(file_stat.st_mode)) printf("Директория\n");
    else if (S_ISCHR(file_stat.st_mode)) printf("Символьное устройство\n");
    else if (S_ISBLK(file_stat.st_mode)) printf("Блочное устройство\n");
    else if (S_ISFIFO(file_stat.st_mode)) printf("FIFO/pipe\n");
    else if (S_ISLNK(file_stat.st_mode)) printf("Символическая ссылка\n");
    else if (S_ISSOCK(file_stat.st_mode)) printf("Сокет\n");
    
    return 0;
}

/* Компиляция: gcc -o fileinfo fileinfo.c
   Использование: ./fileinfo /etc/passwd
*/
```

## Файл как абстракция в языке C и ОС

Операционная система предоставляет абстрактный уровень доступа к данным, скрывая детали работы конкретного железа. Файловая система, как компонент ОС, отвечает за организацию хранения и поиск объектов по именам. В разных ОС под термином "файл" могут подразумеваться разные внутренние структуры данных.

Язык C стремится к переносимости, поэтому предлагает унифицированную абстракцию в виде указателя на структуру FILE. Стандартная библиотека ввода-вывода C (stdio.h) была разработана Деннисом Ритчи как часть языка C в начале 1970-х. Это позволяет работать с именованными данными как в микроконтроллерах, так и на суперкомпьютерах. Стандарт C определяет минимальный набор операций: fopen, fread, fwrite, fclose, fseek.

Использование указателя FILE* вместо самой структуры обеспечивает инкапсуляцию данных. Программист не видит внутренних полей структуры, специфичных для конкретной платформы, и оперирует только адресом. Для доступа к специфическим функциям ОС (например, управлению правами) требуются дополнительные системные вызовы (POSIX: open, read, write вместо fopen, fread, fwrite).

```c
#include <stdio.h>
#include <stdlib.h>

int main(void) {
    // Открытие файла для записи
    FILE *fp = fopen("example.txt", "w");
    if (fp == NULL) {
        perror("fopen");
        return 1;
    }
    
    // Запись данных
    fprintf(fp, "Hello, File I/O!\n");
    fprintf(fp, "Current line: %d\n", __LINE__);
    
    // Закрытие файла
    fclose(fp);
    printf("File written successfully\n");
    
    // Чтение файла
    fp = fopen("example.txt", "r");
    if (fp == NULL) {
        perror("fopen");
        return 1;
    }
    
    char buffer[256];
    printf("\nReading file:\n");
    while (fgets(buffer, sizeof(buffer), fp) != NULL) {
        printf("  %s", buffer);
    }
    
    fclose(fp);
    
    return 0;
}

/*
Режимы открытия файла (fopen):
  "r"   - чтение (файл должен существовать)
  "w"   - запись (создает новый или перезаписывает)
  "a"   - добавление (append, в конец файла)
  "r+"  - чтение и запись (файл должен существовать)
  "w+"  - чтение и запись (создает новый)
  "a+"  - чтение и добавление

Бинарный режим: добавить 'b' (например, "rb", "wb")
  - В текстовом режиме: \n может преобразовываться в \r\n (Windows)
  - В бинарном режиме: данные читаются/пишутся как есть
*/
```

## Специальные файлы и виртуальные устройства

Концепция "everything is a file", популяризированная в Unix-системах (Ken Thompson, 1969-1971), позволяет обращаться к устройствам через файловый интерфейс. Это дает возможность использовать стандартные утилиты для записи настроек драйверов или чтения данных с датчиков. Существуют виртуальные файлы, которые не занимают места на физическом диске.

Ярким примером является **/dev/null** (или NUL в Windows) — файл, который всегда пуст и поглощает любые записанные в него данные. Файл **/dev/zero** служит бесконечным источником нулевых байтов при чтении. Для получения случайных чисел используются виртуальные устройства:
- **/dev/random** — криптографически стойкий генератор (может блокироваться при нехватке энтропии)
- **/dev/urandom** — некриптографический генератор (не блокируется)

Файлы устройств, такие как LPT, COM или современные объекты в /dev/, связывают программный код с физическими ножками процессора или виртуальными устройствами. Через файлы **/proc** (появился в Plan 9, затем в Linux) и **/sys** (sysfs, появился в Linux 2.6, 2003) можно получать информацию о состоянии всей операционной системы.

```c
#include <stdio.h>
#include <unistd.h>

// Демонстрация работы со специальными файлами
int main(void) {
    // /dev/null - "черная дыра"
    FILE *null = fopen("/dev/null", "w");
    if (null != NULL) {
        fprintf(null, "This data disappears into the void\n");
        fprintf(null, "So does this\n");
        fclose(null);
        printf("/dev/null: Data written and discarded\n\n");
    }
    
    // /dev/zero - бесконечный источник нулей
    FILE *zero = fopen("/dev/zero", "r");
    if (zero != NULL) {
        unsigned char buffer[16];
        fread(buffer, 1, 16, zero);
        
        printf("/dev/zero: First 16 bytes: ");
        for (int i = 0; i < 16; i++) {
            printf("%02X ", buffer[i]);
        }
        printf("\n\n");
        fclose(zero);
    }
    
    // /dev/urandom - случайные байты
    FILE *urandom = fopen("/dev/urandom", "r");
    if (urandom != NULL) {
        unsigned char random_bytes[16];
        fread(random_bytes, 1, 16, urandom);
        
        printf("/dev/urandom: Random bytes: ");
        for (int i = 0; i < 16; i++) {
            printf("%02X ", random_bytes[i]);
        }
        printf("\n\n");
        fclose(urandom);
    }
    
    // /proc/cpuinfo - информация о процессоре
    FILE *cpuinfo = fopen("/proc/cpuinfo", "r");
    if (cpuinfo != NULL) {
        char line[256];
        int count = 0;
        printf("/proc/cpuinfo: First 3 lines:\n");
        while (fgets(line, sizeof(line), cpuinfo) && count++ < 3) {
            printf("  %s", line);
        }
        fclose(cpuinfo);
    }
    
    return 0;
}

/*
Специальные файлы в Unix:
  /dev/null     - "черная дыра" для данных
  /dev/zero     - источник нулевых байтов
  /dev/random   - криптографически стойкий ГПСЧ
  /dev/urandom  - быстрый ГПСЧ
  /dev/tty      - управляющий терминал процесса
  /proc/...     - информация о процессах и системе
  /sys/...      - информация об устройствах и драйверах
*/
```

## Классификация файлов по типу доступа

По способу взаимодействия с данными файлы делятся на устройства с последовательным и произвольным доступом.

**Последовательный доступ (sequential access)** подразумевает, что данные читаются строго по порядку. Это характерно для:
- Сетевых потоков (TCP sockets)
- Pipes и FIFO
- Генераторов случайных чисел (/dev/random)
- Магнитных лент (tape drives — исторически важный носитель данных в 1950-1980-х)

**Произвольный доступ (random access)** позволяет программе мгновенно переходить к любому байту внутри файла. Это свойство обычных (regular) файлов, хранящихся на дисках или флешках. Для реализации таких прыжков в языке C используется функция **fseek()**, работающая с блоками байтов.

Концепция произвольного доступа стала возможной с появлением жестких дисков. IBM 305 RAMAC (1956) был первым компьютером с HDD, обеспечивавшим произвольный доступ к данным (в отличие от магнитных лент).

```c
#include <stdio.h>
#include <string.h>

// Демонстрация последовательного vs произвольного доступа
int main(void) {
    const char *filename = "access_demo.dat";
    
    // Создание файла с данными
    FILE *fp = fopen(filename, "wb");
    if (fp == NULL) {
        perror("fopen");
        return 1;
    }
    
    // Запись структурированных данных
    for (int i = 0; i < 10; i++) {
        int value = i * 100;
        fwrite(&value, sizeof(int), 1, fp);
    }
    fclose(fp);
    printf("File created with 10 integers\n\n");
    
    // ПОСЛЕДОВАТЕЛЬНЫЙ ДОСТУП
    printf("Sequential access (reading all):\n");
    fp = fopen(filename, "rb");
    if (fp != NULL) {
        int value;
        while (fread(&value, sizeof(int), 1, fp) == 1) {
            printf("  %d", value);
        }
        printf("\n\n");
        fclose(fp);
    }
    
    // ПРОИЗВОЛЬНЫЙ ДОСТУП
    printf("Random access (reading specific positions):\n");
    fp = fopen(filename, "rb");
    if (fp != NULL) {
        int value;
        
        // Прыжок к 5-му элементу (индекс 4)
        fseek(fp, 4 * sizeof(int), SEEK_SET);
        fread(&value, sizeof(int), 1, fp);
        printf("  Element [4]: %d\n", value);
        
        // Прыжок к последнему элементу
        fseek(fp, -sizeof(int), SEEK_END);
        fread(&value, sizeof(int), 1, fp);
        printf("  Last element: %d\n", value);
        
        // Текущая позиция
        long pos = ftell(fp);
        printf("  Current position: %ld bytes\n", pos);
        
        fclose(fp);
    }
    
    return 0;
}

/*
fseek() параметры:
  fseek(fp, offset, whence)
  
  whence:
    SEEK_SET - от начала файла
    SEEK_CUR - от текущей позиции
    SEEK_END - от конца файла
  
  ftell() - возвращает текущую позицию в байтах
  
Ограничения:
  - fseek() не работает с pipes, sockets, терминалами
  - Только для regular files
*/
```

## Наполнение файлов: текстовые против бинарных

С точки зрения операционной системы и файловой системы разницы между текстовыми и бинарными файлами не существует. Любой файл — это просто последовательность байтов, которую система не интерпретирует самостоятельно. Деление на типы происходит на уровне прикладных программ и восприятия пользователя.

**Текстовые файлы** — это те, которые мы договорились интерпретировать как последовательность символов, разделенную на строки. В конце каждой такой записи переменной длины ставится специальный признак конца строки:
- Unix/Linux: LF (Line Feed, \n, ASCII 10)
- Windows: CR+LF (Carriage Return + Line Feed, \r\n, ASCII 13+10)
- старые Mac (до OS X): CR (Carriage Return, \r, ASCII 13)

Для компьютера эти данные остаются такими же байтами, как и в любом другом файле.

**Бинарные (двоичные) файлы** обычно содержат данные, предназначенные для непосредственного считывания структурами программы. Если открыть такой файл как текстовый, он будет выглядеть как набор бессмысленных символов, так как не предназначен для чтения человеком. При работе в языке C в двоичном режиме программист получает все байты «как есть», без скрытой обработки последовательностей.

```c
#include <stdio.h>
#include <string.h>

// Демонстрация текстового vs бинарного режима
int main(void) {
    // ТЕКСТОВЫЙ РЕЖИМ
    printf("=== TEXT MODE ===\n");
    FILE *text = fopen("text.txt", "w");
    if (text != NULL) {
        fprintf(text, "Line 1\n");
        fprintf(text, "Line 2\n");
        fprintf(text, "Line 3\n");
        fclose(text);
    }
    
    // Чтение в текстовом режиме
    text = fopen("text.txt", "r");
    if (text != NULL) {
        char line[100];
        printf("Reading text file:\n");
        while (fgets(line, sizeof(line), text) != NULL) {
            printf("  %s", line);
        }
        fclose(text);
    }
    
    // БИНАРНЫЙ РЕЖИМ
    printf("\n=== BINARY MODE ===\n");
    
    // Структура для записи
    struct Record {
        int id;
        float value;
        char name[20];
    };
    
    struct Record rec1 = {1, 3.14f, "Alice"};
    struct Record rec2 = {2, 2.71f, "Bob"};
    
    FILE *bin = fopen("data.bin", "wb");
    if (bin != NULL) {
        fwrite(&rec1, sizeof(struct Record), 1, bin);
        fwrite(&rec2, sizeof(struct Record), 1, bin);
        fclose(bin);
        printf("Binary data written\n");
    }
    
    // Чтение бинарных данных
    bin = fopen("data.bin", "rb");
    if (bin != NULL) {
        struct Record rec;
        printf("\nReading binary data:\n");
        while (fread(&rec, sizeof(struct Record), 1, bin) == 1) {
            printf("  ID: %d, Value: %.2f, Name: %s\n",
                   rec.id, rec.value, rec.name);
        }
        fclose(bin);
    }
    
    // Размер файлов
    printf("\nFile sizes:\n");
    FILE *f = fopen("text.txt", "rb");
    fseek(f, 0, SEEK_END);
    printf("  text.txt: %ld bytes\n", ftell(f));
    fclose(f);
    
    f = fopen("data.bin", "rb");
    fseek(f, 0, SEEK_END);
    printf("  data.bin: %ld bytes\n", ftell(f));
    fclose(f);
    
    return 0;
}

/*
Текстовый режим ("r", "w"):
  - Переводы строк преобразуются: \n ↔ \r\n (Windows)
  - EOF (0x1A) может быть интерпретирован как конец файла
  - Подходит для текста, читаемого человеком

Бинарный режим ("rb", "wb"):
  - Данные читаются/пишутся как есть, без преобразований
  - Используется для структур, изображений, аудио, видео
  - Более предсказуемое поведение
*/
```

## Управляющие последовательности и символы

В текстовых файлах, помимо самого текста, содержатся управляющие коды, которые исторически служили для команд принтерам и терминалам. ASCII (American Standard Code for Information Interchange, 1963) определил стандартные коды для первых 128 символов.

К управляющим символам относятся:
- **LF** (Line Feed, \n, ASCII 10) — перевод строки
- **CR** (Carriage Return, \r, ASCII 13) — возврат каретки
- **HT** (Horizontal Tab, \t, ASCII 9) — табуляция
- **BELL** (\a, ASCII 7) — звуковой сигнал (в древних телетайпах физически звонил колокольчик)
- **BS** (Backspace, \b, ASCII 8) — возврат на один символ
- **FF** (Form Feed, \f, ASCII 12) — перевод страницы (на принтере)
- **VT** (Vertical Tab, \v, ASCII 11) — вертикальная табуляция

Особое место занимает символ **Escape** (ESC, код 27), который служит началом для комбинированных команд управления терминалом. С помощью **ANSI escape sequences** (стандартизированы ANSI X3.64 в 1979), начинающихся с ESC[, можно:
- Изменять цвет текста и фона
- Делать текст жирным, курсивом, подчеркнутым
- Управлять положением курсора
- Очищать экран

Также критически важно помнить о символе **EOF** (End of File). В текстовом режиме Windows символ 0x1A (Ctrl-Z) традиционно интерпретировался как конец файла (наследие CP/M). В текстовом режиме чтение может внезапно прекратиться при встрече такого байта. В двоичном режиме этот байт будет считан как обычное числовое значение.

```c
#include <stdio.h>

// Демонстрация управляющих последовательностей
int main(void) {
    printf("=== Базовые управляющие символы ===\n");
    printf("Line 1\nLine 2\n");  // \n - новая строка
    printf("Tab\there\n");        // \t - табуляция
    printf("Backslash: \\ Quote: \" Single: \'\n");
    printf("\a");                  // \a - BELL (звуковой сигнал)
    
    printf("\n=== ANSI escape sequences ===\n");
    // ANSI цвета (работают в большинстве терминалов)
    printf("\033[31mRed text\033[0m\n");      // Красный
    printf("\033[32mGreen text\033[0m\n");    // Зеленый
    printf("\033[34mBlue text\033[0m\n");     // Синий
    printf("\033[1mBold text\033[0m\n");      // Жирный
    printf("\033[4mUnderlined\033[0m\n");     // Подчеркнутый
    printf("\033[7mInverted\033[0m\n");       // Инвертированный
    
    // Управление курсором
    printf("\033[2J");      // Очистить экран
    printf("\033[H");       // Курсор в (0,0)
    printf("\033[5;10HText at row 5, column 10\n");
    
    // Возврат курсора для нормального вывода
    printf("\033[10;1H");
    
    printf("\n=== Коды ASCII управляющих символов ===\n");
    printf("NULL: %d, BELL: %d, BS: %d, TAB: %d\n", 0, 7, 8, 9);
    printf("LF: %d, VT: %d, FF: %d, CR: %d\n", 10, 11, 12, 13);
    printf("ESC: %d, SPACE: %d, DEL: %d\n", 27, 32, 127);
    
    return 0;
}

/*
История управляющих кодов:

1. ASCII (1963) - определил коды 0-127
2. Телетайпы (1960-е) - физические устройства с бумажной лентой
   - BELL физически звонил
   - CR возвращал каретку (печатающую головку) влево
   - LF продвигал бумагу на строку
3. VT100 (DEC, 1978) - первый широко распространенный терминал
   с поддержкой ANSI escape sequences
4. ANSI X3.64 (1979) - стандарт управляющих последовательностей

Современные эмуляторы терминала (xterm, gnome-terminal, iTerm2)
эмулируют поведение VT100 и понимают ANSI sequences.
*/
```

## История интерфейсов: консоль, терминал, панель управления

Термины «консоль» и «терминал» часто путают, но они имеют разное историческое происхождение.

**Консоль** (от латинского consolidare — укреплять, объединять) — это рабочее место оператора, непосредственно подключенное к компьютеру для управления системой и загрузки. Исторически она могла выглядеть как:
- **Панель с тумблерами и лампочками** (1940-1950-е) — ENIAC, ранние компьютеры
- **Телетайп** (1960-1970-е) — электромеханическая печатная машинка (например, Teletype Model 33, 1963)
- **Видеотерминал** (1970-1980-е) — экран с клавиатурой

**Терминал** (от латинского terminus — граница, конец) является оконечным устройством в сети, через которое пользователь взаимодействует с центральной машиной. Первые терминалы были алфавитно-цифровыми и не умели рисовать графику:
- **VT52** (DEC, 1975) — один из первых видеотерминалов
- **VT100** (DEC, 1978) — стал де-факто стандартом, поддерживал ANSI escape sequences
- **VT220** (DEC, 1983) — расширенная версия VT100

То, что современные программисты видят на экранах своих ноутбуков, является **эмулятором терминала** (terminal emulator), который программно воспроизводит поведение древних физических устройств:
- **xterm** (1984, X Window System) — классический эмулятор для Unix
- **GNOME Terminal**, **Konsole**, **iTerm2**, **Windows Terminal** — современные эмуляторы

Важно понимать, что `/dev/tty` в Unix — это устройство управляющего терминала процесса, виртуальная абстракция, которая может указывать на физическое устройство, псевдотерминал (pty) или вообще отсутствовать (для демонов).

```c
#include <stdio.h>
#include <unistd.h>
#include <termios.h>

// Демонстрация работы с терминалом
int main(void) {
    // Проверка, является ли stdin терминалом
    if (isatty(STDIN_FILENO)) {
        printf("stdin is a terminal\n");
        
        // Получение имени терминала
        char *tty = ttyname(STDIN_FILENO);
        if (tty != NULL) {
            printf("Terminal device: %s\n", tty);
        }
        
        // Получение параметров терминала
        struct termios term;
        if (tcgetattr(STDIN_FILENO, &term) == 0) {
            printf("Terminal settings retrieved\n");
            printf("Input speed: %d baud\n", cfgetispeed(&term));
            printf("Output speed: %d baud\n", cfgetospeed(&term));
        }
    } else {
        printf("stdin is NOT a terminal (redirected or pipe)\n");
    }
    
    // Размер терминала (если это tty)
    if (isatty(STDOUT_FILENO)) {
        printf("\nTerminal emulates VT100-compatible device\n");
        printf("Supports ANSI escape sequences\n");
    }
    
    return 0;
}

/*
Историческая справка:

1. Телетайпы (1960-е):
   - Скорость: 10-15 символов/сек (110 baud)
   - Печать на бумаге
   - Физические устройства с механикой

2. VT100 (1978):
   - Первый массовый видеотерминал с escape sequences
   - Стал стандартом де-факто
   - Экран 24x80 символов

3. Эмуляторы (1980-е - сегодня):
   - Программная эмуляция VT100/VT220
   - Поддержка Unicode, цвета, графики
   - xterm (1984), GNOME Terminal, iTerm2, Windows Terminal

/dev/tty в Unix:
  - Виртуальное устройство управляющего терминала
  - Каждый процесс может иметь свой управляющий терминал
  - Запись в /dev/tty всегда идет на терминал процесса
*/
```

## Файлы как средство обмена данными

Файлы служат не только для долговременного хранения, но и для обмена данными между процессами. В Unix существует концепция **pipe** (канал) и **FIFO** (named pipe, именованный канал), которые являются специальными файлами:
- **Anonymous pipe** (|) — создается системным вызовом pipe(), существует только между родственными процессами
- **Named pipe (FIFO)** — создается командой mkfifo, имеет имя в файловой системе, может использоваться несвязанными процессами

Концепция pipes была введена Дугом Макилроем (Doug McIlroy) в Unix Version 3 (1973) и стала одной из фундаментальных идей Unix philosophy: "Write programs that do one thing well and work together."

Также файлы используются для:
- **Lock files** — файлы-блокировки для синхронизации процессов
- **Socket files** — Unix domain sockets для межпроцессного взаимодействия
- **Configuration files** — текстовые файлы с настройками (INI, JSON, YAML, TOML)

## Форматы файлов и магические числа

Для определения типа файла независимо от расширения используются **magic numbers** (магические числа) — специфические последовательности байтов в начале файла.

Примеры magic numbers:
- **JPEG**: `FF D8 FF` (начало), `FF D9` (конец)
- **PNG**: `89 50 4E 47 0D 0A 1A 0A` (‰PNG\r\n\x1A\n)
- **GIF87a**: `47 49 46 38 37 61` (GIF87a)
- **GIF89a**: `47 49 46 38 39 61` (GIF89a)
- **PDF**: `25 50 44 46` (%PDF)
- **ZIP**: `50 4B 03 04` (PK\x03\x04)
- **ELF**: `7F 45 4C 46` (\x7FELF)
- **PE (Windows EXE)**: `4D 5A` (MZ — Mark Zbikowski, автор формата)

Утилита `file` в Unix использует базу данных magic numbers (обычно `/usr/share/misc/magic`) для определения типов файлов.

```c
#include <stdio.h>
#include <string.h>

// Определение типа файла по magic number
void identify_file(const char *filename) {
    FILE *fp = fopen(filename, "rb");
    if (fp == NULL) {
        perror("fopen");
        return;
    }
    
    unsigned char magic[8];
    size_t n = fread(magic, 1, 8, fp);
    fclose(fp);
    
    if (n < 4) {
        printf("%s: Too small to identify\n", filename);
        return;
    }
    
    printf("%s: ", filename);
    
    // Проверка различных форматов
    if (magic[0] == 0xFF && magic[1] == 0xD8 && magic[2] == 0xFF) {
        printf("JPEG image\n");
    }
    else if (magic[0] == 0x89 && magic[1] == 'P' && 
             magic[2] == 'N' && magic[3] == 'G') {
        printf("PNG image\n");
    }
    else if (magic[0] == 'G' && magic[1] == 'I' && 
             magic[2] == 'F' && magic[3] == '8') {
        printf("GIF image\n");
    }
    else if (magic[0] == '%' && magic[1] == 'P' && 
             magic[2] == 'D' && magic[3] == 'F') {
        printf("PDF document\n");
    }
    else if (magic[0] == 'P' && magic[1] == 'K' && 
             magic[2] == 0x03 && magic[3] == 0x04) {
        printf("ZIP archive\n");
    }
    else if (magic[0] == 0x7F && magic[1] == 'E' && 
             magic[2] == 'L' && magic[3] == 'F') {
        printf("ELF executable\n");
    }
    else if (magic[0] == 'M' && magic[1] == 'Z') {
        printf("PE/Windows executable\n");
    }
    else if (magic[0] == '#' && magic[1] == '!') {
        printf("Script with shebang\n");
    }
    else {
        printf("Unknown format (magic: %02X %02X %02X %02X)\n",
               magic[0], magic[1], magic[2], magic[3]);
    }
}

int main(int argc, char *argv[]) {
    if (argc < 2) {
        fprintf(stderr, "Usage: %s <file1> [file2] ...\n", argv[0]);
        return 1;
    }
    
    for (int i = 1; i < argc; i++) {
        identify_file(argv[i]);
    }
    
    return 0;
}

/*
Использование:
  gcc -o identify identify.c
  ./identify /bin/ls image.jpg document.pdf
  
Вывод:
  /bin/ls: ELF executable
  image.jpg: JPEG image
  document.pdf: PDF document
*/
```

## Метаданные и организация файловых систем

Файловая система является функциональной компонентой ОС, которая определяет способы организации и поиска данных по именам. Внутренняя структура ФС может включать такие понятия, как **inode** (index node, индексный дескриптор), хранящий метаданные файла.

Концепция inode появилась в Unix (1971). Inode содержит:
- Тип файла (обычный, директория, устройство, symlink)
- Права доступа (rwxrwxrwx)
- Владелец (UID, GID)
- Размер файла
- Временные метки (atime, mtime, ctime)
- Количество жестких ссылок
- Указатели на блоки данных на диске

Важно: inode НЕ содержит имя файла! Имя хранится в директории, которая представляет собой таблицу соответствий "имя → номер inode".

Основные файловые системы:
- **FAT (File Allocation Table)** — Microsoft, 1977, простая, ограниченная
- **ext2** (Second Extended File System) — Linux, 1993, Rémy Card
- **ext3** — Linux, 2001, добавлено журналирование
- **ext4** — Linux, 2008, текущий стандарт для Linux
- **NTFS** (New Technology File System) — Microsoft, 1993, Windows NT
- **HFS+** — Apple, 1998, Mac OS
- **APFS** (Apple File System) — Apple, 2017, заменил HFS+
- **ZFS** — Sun Microsystems, 2005, продвинутая ФС с copy-on-write
- **Btrfs** (B-tree FS) — Linux, Oracle, 2009

Метаданные включают временные метки:
- **atime** (access time) — время последнего доступа к содержимому
- **mtime** (modification time) — время последнего изменения содержимого
- **ctime** (change time) — время последнего изменения метаданных inode

Механизмы связей:
- **Hardlinks (жесткие ссылки)** — несколько имен для одного inode. Удаление одного имени не удаляет файл, пока существуют другие ссылки.
- **Softlinks/Symlinks (символические ссылки)** — специальный файл, содержащий путь к другому файлу. Работает как ярлык.

Дедупликация позволяет файловой системе экономить место, обнаруживая идентичные блоки данных в разных файлах и храня их в единственном экземпляре. Это актуально для облачных хранилищ (Dropbox, Google Drive) и систем с большим количеством повторяющегося контента. Файловые системы ZFS и Btrfs поддерживают дедупликацию на уровне ФС.

```c
#include <stdio.h>
#include <sys/stat.h>
#include <unistd.h>

// Демонстрация hardlinks и symlinks
int main(void) {
    const char *original = "original.txt";
    const char *hardlink = "hardlink.txt";
    const char *symlink = "symlink.txt";
    
    // Создание оригинального файла
    FILE *fp = fopen(original, "w");
    if (fp != NULL) {
        fprintf(fp, "This is the original file\n");
        fclose(fp);
    }
    
    // Создание hardlink
    if (link(original, hardlink) == 0) {
        printf("Hardlink created: %s -> %s\n", hardlink, original);
    }
    
    // Создание symlink
    if (symlink(original, symlink) == 0) {
        printf("Symlink created: %s -> %s\n", symlink, original);
    }
    
    // Проверка inode
    struct stat st_orig, st_hard, st_sym;
    stat(original, &st_orig);
    stat(hardlink, &st_hard);
    lstat(symlink, &st_sym);  // lstat для symlink (не разыменовывает)
    
    printf("\nInode numbers:\n");
    printf("  %s: %lu (links: %lu)\n", 
           original, st_orig.st_ino, st_orig.st_nlink);
    printf("  %s: %lu (links: %lu)\n", 
           hardlink, st_hard.st_ino, st_hard.st_nlink);
    printf("  %s: %lu (is symlink)\n", 
           symlink, st_sym.st_ino);
    
    if (st_orig.st_ino == st_hard.st_ino) {
        printf("\n✓ Hardlink: Same inode as original\n");
    }
    
    if (S_ISLNK(st_sym.st_mode)) {
        printf("✓ Symlink: Is a symbolic link\n");
        
        char target[256];
        ssize_t len = readlink(symlink, target, sizeof(target)-1);
        if (len != -1) {
            target[len] = '\0';
            printf("  Points to: %s\n", target);
        }
    }
    
    // Удаление hardlink не удаляет файл
    printf("\nRemoving hardlink...\n");
    unlink(hardlink);
    stat(original, &st_orig);
    printf("After removal: %s still has %lu link(s)\n",
           original, st_orig.st_nlink);
    
    // Cleanup
    unlink(symlink);
    unlink(original);
    
    return 0;
}

/*
Hardlink vs Symlink:

Hardlink:
  - Несколько имен для одного inode
  - Все имена равноправны
  - Нельзя создавать для директорий (кроме . и ..)
  - Нельзя создавать между разными файловыми системами
  - Файл удаляется, когда счетчик ссылок = 0

Symlink:
  - Отдельный файл, содержащий путь
  - Может указывать на несуществующий файл (broken link)
  - Может указывать на директорию
  - Может пересекать границы файловых систем
  - При удалении symlink оригинальный файл остается
*/
```

## Типовые ошибки и неверные интерпретации

1. **Файл как одномерный массив**: Новички часто забывают, что не все файлы поддерживают произвольный доступ (random access). Попытка «перемотки» сетевого потока или вывода устройства через fseek может привести к неопределенному поведению.

2. **Игнорирование символа EOF**: В текстовом режиме символ с кодом 0x1A (Ctrl-Z) может быть интерпретирован как признак конца файла (наследие CP/M). Программа прекратит чтение, даже если за этим байтом следуют другие полезные данные.

3. **Сравнение строк в файлах**: Сравнение двух строк, считанных из файла, с помощью оператора == проверяет равенство адресов указателей, а не содержимого. Для корректного поиска по именам в файле необходимо использовать strcmp.

4. **Ресурсные утечки**: Открытие множества файлов без вызова fclose приводит к исчерпанию лимита открытых дескрипторов в ОС (обычно 1024 на процесс). В долгоживущих системных процессах это может вызвать отказ в обслуживании.

5. **Путаница между каталогом и директорией**: Пользователи часто смешивают эти понятия. Директория — это техническая структура данных в ФС (таблица "имя → inode"), тогда как «папка» или «каталог» являются более высокоуровневыми абстракциями интерфейса.

6. **Забывание проверки на NULL**: После fopen() необходимо всегда проверять результат на NULL. Работа с NULL указателем вызывает segmentation fault.

7. **Буферизация вывода**: Данные, записанные через fprintf/fwrite, могут оставаться в буфере и не попадать на диск до вызова fflush() или fclose().

## Математические основы

Работа с файлами опирается на теорию графов, так как файловая система организует поиск и хранение данных с использованием структур типа деревьев. Многие современные файловые системы используют B-trees (B-деревья, Rudolf Bayer, 1972) или красно-черные деревья (red-black trees, Rudolf Bayer, 1972, название от Leonidas J. Guibas & Robert Sedgewick, 1978) для индексирования, что обеспечивает высокую скорость доступа O(log n).

Интерпретация данных в файлах требует владения двоичной и шестнадцатеричной системами счисления, так как на низком уровне файл представляет собой последовательность байтов, где каждый байт — это число от 0 до 255 (0x00–0xFF).

Понятие смещения (offset) основывается на линейной алгебре: адрес любого байта в файле при произвольном доступе вычисляется как:

**offset = base_address + relative_position**

Для структурированных файлов:

**offset_field = offset_record + offset_within_record**
**offset_record = record_number × sizeof(record)**

Файловые системы используют различные алгоритмы размещения данных:
- **Contiguous allocation** — непрерывное размещение (используется в CD-ROM)
- **Linked allocation** — связанное размещение (FAT)
- **Indexed allocation** — индексное размещение (inode в Unix)

Дедупликация данных основана на хэш-функциях (например, SHA-256) для идентификации идентичных блоков данных.

## Вопросы для собеседования

1. **Что такое файл с точки зрения операционной системы?**
   Файл — это именованная последовательность байтов, хранящаяся на носителе, которую сама ОС не интерпретирует, оставляя это прикладным программам.

2. **Когда появилась первая файловая система?**
   IBM 305 RAMAC, 1956 год — первый компьютер с жестким диском и файловой системой.

3. **Кто ввел концепцию "everything is a file"?**
   Unix (Ken Thompson & Dennis Ritchie, 1969-1971). Эта философия позволила унифицировать доступ к устройствам, файлам и процессам.

4. **Когда появилась концепция inode?**
   В Unix, 1971 год. Inode хранит метаданные файла, но не его имя.

5. **Кто изобрел pipes и когда?**
   Дуг Макилрой (Doug McIlroy), Unix Version 3, 1973 год.

6. **Откуда взялось ограничение 8.3 для имен файлов?**
   CP/M (Control Program for Microcomputers, Gary Kildall, 1974), унаследовано MS-DOS и ранними Windows.

7. **В чем преимущество использования указателя FILE* в языке C?**
   Это обеспечивает инкапсуляцию: программист работает с абстрактным адресом структуры, не видя внутренних полей, специфичных для конкретной ОС, что делает код переносимым.

8. **Для чего используются файлы /dev/null и /dev/zero?**
   /dev/null — это «черная дыра», поглощающая любые записанные данные; /dev/zero — бесконечный источник нулевых байтов при чтении.

9. **Существует ли разница между текстовыми и бинарными файлами для файловой системы?**
   Нет, для ФС любой файл — это просто набор байтов. Разница существует только на уровне интерпретации данных программой или пользователем.

10. **Что такое «магические числа» в контексте файлов?**
    Это специфические последовательности байтов в начале файла (например, FF D8 FF для JPEG), позволяющие программам определять формат данных независимо от расширения.

11. **В чем разница между последовательным и произвольным доступом?**
    При последовательном доступе данные читаются строго по порядку, при произвольном — можно мгновенно перейти к любому байту с помощью функции fseek.

12. **Зачем нужно закрывать файлы функцией fclose?**
    Вывод в C часто буферизуется; если не закрыть файл, последние записанные данные могут остаться в памяти и не попасть на диск. Также освобождаются дескрипторы файлов.

13. **Как работает механизм Shebang (#!)?**
    Если файл имеет атрибут исполняемого и начинается с этих двух байтов, ядро ОС считывает путь за ними и передает файл указанному интерпретатору для выполнения.

14. **Что такое binfmt_misc в Linux?**
    Это механизм (добавлен в kernel 2.1.43, 1997), позволяющий системе запускать файлы «чужих» форматов (например, Windows .exe) через соответствующие эмуляторы на основе сигнатур заголовка.

15. **Чем исторически отличается консоль от терминала?**
    Консоль — это рабочее место оператора, подключенное непосредственно к машине для управления ею; терминал — оконечное устройство связи в сети (VT100, VT220).

16. **Почему расширение файла считается «атавизмом» в современных ОС?**
    Реальный тип и свойства данных сегодня определяются их внутренней структурой (magic numbers), а расширение служит лишь подсказкой для пользователя.

17. **Как управляющие коды ASCII влияют на вывод текста?**
    Они не печатаются как символы, а подают команды устройству (например, BELL (ASCII 7) вызывает звуковой сигнал, а CR (13) возвращает курсор в начало строки).

18. **Что такое VT100 и его значение?**
    DEC VT100 (1978) — видеотерминал, ставший де-факто стандартом. Поддерживал ANSI escape sequences. Современные эмуляторы терминала эмулируют его поведение.

19. **В чем разница между hardlink и symlink?**
    Hardlink — несколько имен для одного inode (счетчик ссылок). Symlink — отдельный файл, содержащий путь к другому файлу (может быть broken).

20. **Что такое временные метки atime, mtime, ctime?**
    atime — время доступа, mtime — время изменения содержимого, ctime — время изменения метаданных inode.

21. **Назовите основные файловые системы и их даты создания.**
    FAT (1977), ext2 (1993), ext3 (2001), ext4 (2008), NTFS (1993), HFS+ (1998), APFS (2017), ZFS (2005), Btrfs (2009).

22. **Что такое дедупликация в файловых системах?**
    Обнаружение и устранение дублирующихся блоков данных, хранение их в единственном экземпляре. Поддерживается в ZFS и Btrfs.

## Итоги и следующие шаги

- Файл является универсальной абстракцией именованных данных в современных ОС.
- История: IBM 305 RAMAC (1956) → Multics (1965) → Unix "everything is a file" (1969-1971) → современные ФС.
- Принципы «все есть файл» позволяют унифицированно работать с дисками, устройствами и системными настройками.
- Метаданные файла (права доступа, временные метки, inode) хранятся отдельно от самих данных в структурах файловой системы.
- Работа с файлами в языке C требует обязательного контроля состояния указателя (NULL-check) и корректного завершения потока.
- Буферизация повышает производительность, но накладывает ответственность на программиста по сбросу данных (fflush/fclose).
- Различие текстового и бинарного режимов в C влияет на обработку символов переноса строки и признака конца файла (EOF, 0x1A).
- Эмуляторы терминала сохраняют протоколы управления физических устройств 50-летней давности (VT100, 1978), включая ANSI-последовательности (1979).
- Исполняемость файла в Unix-системах определяется атрибутом, а не расширением имени.
- Magic numbers позволяют определять формат файла независимо от расширения.
- Pipes (Doug McIlroy, 1973) и философия Unix: "Write programs that do one thing well."
- Hardlinks и symlinks — разные механизмы для ссылок на файлы.
- Файловые системы эволюционировали: FAT → ext2/3/4, NTFS, APFS, ZFS с продвинутыми возможностями.

## Связанные темы и лекции

Материал по файлам тесно переплетается с темами:

- **Операционные системы**: Детально разбираются механизмы inode, hardlinks, softlinks, виртуальная память, page cache.
- **Архитектура ЭВМ**: Работа шин ввода-вывода, контроллеров устройств, DMA (Direct Memory Access).
- **Представление данных**: Управляющие последовательности ASCII, кодировки (UTF-8, UTF-16), endianness.
- **Системное программирование**: Низкоуровневые вызовы (open, read, write, lseek), работа с дескрипторами файлов, ioctl.
- **Алгоритмы и структуры данных**: B-trees, красно-черные деревья для индексирования в ФС.
- **История вычислительной техники**: Эволюция от перфокарт и магнитных лент к жестким дискам и SSD. Телетайпы, VT100, эмуляторы терминалов.
- **Безопасность**: Права доступа Unix (rwx), ACL (Access Control Lists), атрибуты файлов, безопасное удаление данных.
