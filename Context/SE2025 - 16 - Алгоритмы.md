# Алгоритмы

## Область применения

Данный материал предназначен для студентов первого курса, изучающих основы информатики и программирования. Он требует предварительного понимания базовых конструкций языка С (циклы, условия, структуры) и основ дискретной математики. Материал охватывает теоретические основы алгоритмизации и методы оценки эффективности программ.

## Контекст и мотивация

В программировании важно не просто решить задачу, но и оценить, насколько предложенный метод лучше других. Понимание сложности алгоритмов позволяет предсказывать поведение программы при увеличении объема данных и выбирать экономически оправданные решения. Без формализации процесса вычисления невозможно строго рассуждать о свойствах алгоритмов.

**Примеры ценности понимания сложности:**
- Сортировка 1 млн элементов: O(n²) → ~10¹² операций, O(n log n) → ~2×10⁷ операций — разница в **50 000 раз**
- Google обрабатывает ~8.5 млрд поисковых запросов в день — неэффективный алгоритм невозможен технически
- NASDAQ в 2012 году потерял $440 млн из-за ошибки в алгоритме торговли за 45 минут

## Термины и обозначения

- **Алгоритм (алгорифм)** — точное предписание, определяющее вычислительный процесс, идущий от варьируемых исходных данных к искомому результату.
- **Машина Тьюринга (МТ)** — абстрактная модель вычислителя, состоящая из бесконечной ленты, считывающей головки и таблицы переходов (Alan Turing, 1936).
- **Машина Поста** — альтернативная модель вычислений (Emil Post, 1936), эквивалентная МТ.
- **Вычислительная сложность** — оценка количества элементарных операций, выполняемых алгоритмом.
- **Емкостная сложность** — объем памяти, необходимый алгоритму для хранения промежуточных результатов.
- **Асимптотическая сложность (O-большое)** — характеристика скорости роста трудоемкости алгоритма при стремлении объема входных данных к бесконечности.
- **Амортизационный анализ** — метод оценки средней стоимости операции в последовательности действий, учитывающий взаимосвязь между ними (Robert Tarjan, 1985).
- **Мемоизация** — техника кэширования результатов функции для избежания повторных вычислений.
- **NP-полнота** — класс задач, для которых не найдено полиномиального алгоритма решения.

## Введение в понятие алгоритма

Понятие алгоритма часто путают с методами или конкретными процедурами решения задач. Сортировка сама по себе является **задачей**, у которой может быть множество различных решений-**алгоритмов**. Для строгого обсуждения алгоритмов необходимо опираться на их формальные определения и свойства.

**Ключевое различие:**
- **Задача**: "отсортировать массив чисел по возрастанию"
- **Алгоритм**: конкретный способ решения — пузырьковая сортировка O(n²), быстрая сортировка O(n log n), сортировка слиянием O(n log n), сортировка подсчетом O(n+k)

Одна и та же задача может иметь:
- Алгоритмы с разной вычислительной сложностью
- Алгоритмы с разной емкостной сложностью
- Алгоритмы с разными практическими характеристиками (константами)

## Формальные модели вычислений

В 1930-е годы независимо друг от друга были созданы несколько эквивалентных моделей вычислений:

### Машина Тьюринга (Alan Turing, 1936)

Машина Тьюринга представляет собой кортеж `M = (Q, Γ, b, Σ, δ, q₀, F)`, где:
- **Q** — конечное множество состояний
- **Γ** — алфавит ленты
- **b ∈ Γ** — пустой символ
- **Σ ⊆ Γ \ {b}** — входной алфавит
- **δ: (Q \ F) × Γ → Q × Γ × {L, R}** — функция перехода
- **q₀** — начальное состояние
- **F ⊆ Q** — множество конечных (допускающих) состояний

Работа МТ: головка читает символ, по таблице δ определяет новое состояние, записывает символ и сдвигается влево (L) или вправо (R).

**Ключевые понятия:**
- **Детерминированная МТ** — в каждом состоянии для каждого символа ровно одно действие
- **Недетерминированная МТ** — может выбирать из нескольких действий (теоретическая конструкция)
- **Универсальная МТ** — МТ, которая симулирует любую другую МТ (предшественник современного процессора)

### Машина Поста (Emil Post, 1936)

Более близка к архитектуре современных программ. Вместо "текущей позиции на ленте" хранит метку текущего оператора, переходит между пронумерованными операторами. По мощности эквивалентна МТ.

### Нормальные алгорифмы Маркова (A.A. Markov мл., 1951)

Система замены подстрок в строке по правилам вида `A → B`. Также эквивалентна МТ.

### Лямбда-исчисление (Alonzo Church, 1936)

Формальная система с функциями, применением и абстракцией. Эквивалентна МТ. Основа функционального программирования.

```c
// Эмуляция простейшей машины Тьюринга на C
// Задача: подсчет единиц в бинарной строке (переводим '1' в 'X')

#include <stdio.h>
#include <string.h>

#define TAPE_SIZE 100
#define BLANK '_'

typedef enum { LEFT = -1, RIGHT = 1, STAY = 0 } Direction;

// Состояния машины
typedef enum { Q0, Q1, Q_ACCEPT, Q_REJECT } State;

typedef struct {
    State new_state;
    char write_symbol;
    Direction move;
} Transition;

void run_turing_machine(char *tape, int head_pos) {
    State state = Q0;
    int steps = 0;
    
    printf("Начальная лента: %s\n", tape);
    printf("Начальная позиция головки: %d\n\n", head_pos);
    
    while (state != Q_ACCEPT && state != Q_REJECT && steps < 1000) {
        char current = tape[head_pos];
        Transition t;
        
        // Таблица переходов δ
        // Q0: считаем единицы, заменяем '1' на 'X'
        switch (state) {
            case Q0:
                if (current == '1') {
                    t = (Transition){Q0, 'X', RIGHT};  // Помечаем единицу
                } else if (current == '0') {
                    t = (Transition){Q0, '0', RIGHT};  // Пропускаем нули
                } else {  // BLANK
                    t = (Transition){Q_ACCEPT, BLANK, STAY};  // Конец
                }
                break;
            default:
                t = (Transition){Q_REJECT, current, STAY};
                break;
        }
        
        printf("Шаг %2d: состояние=Q%d, читаем='%c', пишем='%c', "
               "движение=%s\n",
               steps, state, current, t.write_symbol,
               t.move == RIGHT ? "RIGHT" : (t.move == LEFT ? "LEFT" : "STAY"));
        
        tape[head_pos] = t.write_symbol;
        state = t.new_state;
        head_pos += t.move;
        steps++;
    }
    
    printf("\nРезультирующая лента: %s\n", tape);
    printf("Конечное состояние: %s\n",
           state == Q_ACCEPT ? "ACCEPT" : "REJECT");
    
    // Подсчитаем X — количество единиц
    int count = 0;
    for (int i = 0; tape[i] != '\0'; i++) {
        if (tape[i] == 'X') count++;
    }
    printf("Количество единиц: %d\n", count);
}

int main(void) {
    char tape[TAPE_SIZE] = "10110_";  // _ = пустой символ
    run_turing_machine(tape, 0);
    return 0;
}

/*
Машина Тьюринга (1936):
  - Alan Turing — "On Computable Numbers, with an Application 
    to the Entscheidungsproblem"
  - Ответ на Entscheidungsproblem Гильберта: не все проблемы решаемы
  - Доказала существование неразрешимых задач (Halting Problem)
  
Halting Problem (проблема остановки):
  - Нельзя создать алгоритм, который для ЛЮБОЙ программы
    определит, завершится она или зайдет в бесконечный цикл
  - Это первый пример неразрешимой задачи
  - Доказано Тьюрингом через диагонализацию (1936)
*/
```

## Тезис Чёрча — Тьюринга

**Тезис Чёрча-Тьюринга (1936)** утверждает: любая функция, вычисляемая физическим устройством или интуитивно вычислимая человеком, может быть реализована на машине Тьюринга.

Это утверждение является **тезисом, а не теоремой**, потому что:
1. Оно связывает **интуитивное** понятие вычисления (которое нельзя формально определить) с **формальной** моделью (МТ)
2. Невозможно формально доказать утверждение об "интуитивной вычислимости"
3. Можно лишь накапливать косвенные свидетельства (все конкретные вычислимые функции действительно реализуемы на МТ)

**Аргументы в пользу тезиса:**
- МТ, λ-исчисление, машина Поста, алгорифмы Маркова — все эквивалентны
- Ни один контрпример за ~90 лет не найден
- Квантовые компьютеры (QC) не опровергают тезис — они быстрее, но вычисляют те же функции

**Физический тезис:** Физические законы не позволяют построить "гиперкомпьютер", вычисляющий неразрешимые задачи. Ограничивает вычисления конечными процессами.

**Следствие — проблема остановки (Halting Problem):**
Не существует алгоритма, который для произвольной программы P и входа x определяет, завершится ли P(x). Это первая доказанная неразрешимая задача (Turing, 1936).

## Определение и фундаментальные свойства алгоритма

Различные математики давали похожие определения:
- **А.Н. Колмогоров**: система вычислений, заведомо приводящая к решению задачи за конечное число шагов
- **А.А. Марков**: точное предписание, универсальное относительно класса входных данных
- **Кнут** (TAOCP): конечный набор правил, задающий последовательность операций

Алгоритм должен обладать **четырьмя ключевыми свойствами**:

1. **Конечная запись (Finiteness of description)** — описание алгоритма имеет конечный размер
2. **Завершаемость (Termination)** — алгоритм завершается за конечное число шагов для любых корректных входных данных
3. **Универсальность (Definiteness/Generality)** — алгоритм применим к целому классу входных данных, а не к одному конкретному значению
4. **Правильность (Correctness)** — алгоритм действительно решает поставленную задачу, а не просто завершает работу

**Замечание о завершаемости:** Существуют "процедуры" (semi-algorithms), которые завершаются только для части входных данных. Например, наивный поиск делителей для проверки простоты числа — формально алгоритм. Но для некоторых задач доказать завершаемость крайне сложно (Collatz conjecture).

```c
// Демонстрация свойств алгоритма

#include <stdio.h>
#include <stdbool.h>

// ========== СВОЙСТВО 1: КОНЕЧНАЯ ЗАПИСЬ ==========
// Алгоритм Евклида - лаконично записан в нескольких строках,
// несмотря на то что работает на бесконечном классе входных данных

int gcd_euclid(int a, int b) {
    // Алгоритм Евклида (~300 до н.э.) - один из древнейших алгоритмов
    while (b != 0) {
        int temp = b;
        b = a % b;
        a = temp;
    }
    return a;
}

// ========== СВОЙСТВО 2: ЗАВЕРШАЕМОСТЬ ==========

// ХОРОШИЙ пример: всегда завершается
int factorial(int n) {
    if (n <= 0) return 1;        // Базовый случай
    return n * factorial(n - 1); // Рекурсия с убывающим n
}

// ПЛОХОЙ пример: не завершается при n > 1 (бесконечный цикл)
// int bad_algo(int n) {
//     while (n != 1) {
//         if (n % 2 == 0) n = n / 2;  // Гипотеза Коллатца
//         else n = 3 * n + 1;
//     }
//     return n;
// }
// Гипотеза Коллатца (1937): завершается для всех n > 0?
// До сих пор не доказана! (проверено до ~3*10^20)

// ========== СВОЙСТВО 3: УНИВЕРСАЛЬНОСТЬ ==========

// НЕ алгоритм: "прибавить 2 к числу 5" — слишком конкретно
// АЛГОРИТМ: "прибавить b к числу a" — работает для ЛЮБЫХ a, b

int add(int a, int b) {
    return a + b;  // Работает для всего класса целых чисел
}

// ========== СВОЙСТВО 4: ПРАВИЛЬНОСТЬ ==========

// НЕПРАВИЛЬНЫЙ алгоритм проверки простоты (с багом)
bool is_prime_wrong(int n) {
    if (n < 2) return false;
    for (int i = 2; i < n; i++) {
        if (n % i == 0) return false;
    }
    return true;  // Корректен, но...
    // Пропущен случай n = 1? Нет, обработан. Но O(n) — медленно.
}

// ПРАВИЛЬНЫЙ и эффективный алгоритм
bool is_prime_correct(int n) {
    if (n < 2) return false;
    if (n == 2) return true;
    if (n % 2 == 0) return false;
    for (int i = 3; (long long)i * i <= n; i += 2) {
        if (n % i == 0) return false;
    }
    return true;  // O(sqrt(n))
}

int main(void) {
    printf("=== Свойства алгоритма ===\n\n");
    
    printf("НОД(48, 18) = %d  (алгоритм Евклида, ~300 до н.э.)\n",
           gcd_euclid(48, 18));
    
    printf("5! = %d  (алгоритм завершится за 5 шагов)\n\n",
           factorial(5));
    
    printf("Универсальность: add(3, 4) = %d, add(-10, 7) = %d\n\n",
           add(3, 4), add(-10, 7));
    
    printf("Правильность алгоритмов проверки простоты:\n");
    int test_nums[] = {1, 2, 7, 12, 13, 97};
    for (int i = 0; i < 6; i++) {
        int n = test_nums[i];
        printf("  %2d: wrong=%s, correct=%s\n",
               n,
               is_prime_wrong(n) ? "prime" : "not prime",
               is_prime_correct(n) ? "prime" : "not prime");
    }
    
    return 0;
}

/*
Важные неразрешимые задачи (следствие тезиса Чёрча-Тьюринга):
  1. Halting Problem (проблема остановки) — Turing 1936
  2. Проблема соответствия Поста (Post Correspondence Problem)
  3. 10-я проблема Гильберта (Hilbert's 10th Problem) — Matiyasevich 1970
  4. Проблема эквивалентности программ

Разрешимые но трудные задачи (NP-полные):
  1. Задача о выполнимости (SAT) — Cook 1971
  2. Задача коммивояжера (TSP)
  3. Задача о рюкзаке (Knapsack)
  4. Задача о раскраске графа
*/
```

## Понятие сложности алгоритма

Сложность алгоритма позволяет оценить ресурсы, необходимые для его выполнения.

**Виды сложности:**

1. **Вычислительная (временная) сложность** — количество шагов/операций
2. **Емкостная (пространственная) сложность** — расход памяти
3. **Коммуникационная сложность** — объем передаваемых данных (в распределенных системах)
4. **Сложность схемы** — количество логических элементов

**Случаи анализа:**
- **Худший случай** (worst case) — верхняя граница для любых входных данных
- **Лучший случай** (best case) — нижняя граница
- **Средний случай** (average case) — математическое ожидание по всем входным данным

**Экономическая эффективность** учитывает не только быстродействие, но и:
- Стоимость разработки и сопровождения кода
- Простоту реализации и отладки
- Масштабируемость
- Потребление энергии (критично для мобильных устройств)

## Асимптотический анализ и О-символика

Для сравнения алгоритмов используется **асимптотическая оценка**, игнорирующая:
1. Константные множители (зависят от архитектуры)
2. Слагаемые меньшего порядка

**О-нотация введена** в CS Donald Knuth (1973), хотя само понятие использовал Paul Bachmann (1894) и Edmund Landau (1909) в математике.

**Иерархия сложностей (от быстрых к медленным):**
```
O(1) < O(log log n) < O(log n) < O(√n) < O(n) < O(n log n) < O(n²) < O(n³) < O(2ⁿ) < O(n!) < O(nⁿ)
```

**Примеры алгоритмов по классам:**

| Сложность | Пример | n=1000 |
|-----------|--------|--------|
| O(1) | Доступ к элементу массива | 1 оп |
| O(log n) | Бинарный поиск | ~10 оп |
| O(n) | Линейный поиск | 1 000 оп |
| O(n log n) | Быстрая сортировка | ~10 000 оп |
| O(n²) | Пузырьковая сортировка | 1 000 000 оп |
| O(2ⁿ) | Перебор всех подмножеств | 2^1000 ≈ 10^301 оп |

```c
// Демонстрация асимптотической нотации

#include <stdio.h>
#include <math.h>
#include <time.h>

// ========== O(1) — КОНСТАНТНАЯ СЛОЖНОСТЬ ==========
int get_first(int *arr) {
    return arr[0];  // Всегда 1 операция, независимо от размера
}

// ========== O(log n) — ЛОГАРИФМИЧЕСКАЯ ==========
// Бинарный поиск (binary search)
// Идея: Hermann Lotz, 1947; алгоритм: первое упоминание ~1946
int binary_search(int *arr, int size, int target) {
    int left = 0, right = size - 1;
    
    while (left <= right) {
        int mid = left + (right - left) / 2;  // Избегаем переполнения
        if (arr[mid] == target) return mid;
        if (arr[mid] < target) left = mid + 1;
        else right = mid - 1;
    }
    return -1;  // Не найден
}

// ========== O(n) — ЛИНЕЙНАЯ ==========
int linear_search(int *arr, int size, int target) {
    for (int i = 0; i < size; i++) {
        if (arr[i] == target) return i;
    }
    return -1;
}

long long sum_array(int *arr, int size) {
    long long sum = 0;
    for (int i = 0; i < size; i++) {
        sum += arr[i];
    }
    return sum;
}

// ========== O(n log n) — ЛИНЕЙНО-ЛОГАРИФМИЧЕСКАЯ ==========
// Сортировка слиянием (merge sort, John von Neumann, 1945)
void merge(int *arr, int left, int mid, int right) {
    int n1 = mid - left + 1;
    int n2 = right - mid;
    
    int L[n1], R[n2];
    for (int i = 0; i < n1; i++) L[i] = arr[left + i];
    for (int j = 0; j < n2; j++) R[j] = arr[mid + 1 + j];
    
    int i = 0, j = 0, k = left;
    while (i < n1 && j < n2) {
        arr[k++] = (L[i] <= R[j]) ? L[i++] : R[j++];
    }
    while (i < n1) arr[k++] = L[i++];
    while (j < n2) arr[k++] = R[j++];
}

void merge_sort(int *arr, int left, int right) {
    if (left < right) {
        int mid = left + (right - left) / 2;
        merge_sort(arr, left, mid);
        merge_sort(arr, mid + 1, right);
        merge(arr, left, mid, right);
    }
}

// ========== O(n²) — КВАДРАТИЧНАЯ ==========
// Сортировка пузырьком
void bubble_sort(int *arr, int n) {
    for (int i = 0; i < n - 1; i++) {
        for (int j = 0; j < n - i - 1; j++) {
            if (arr[j] > arr[j + 1]) {
                int temp = arr[j];
                arr[j] = arr[j + 1];
                arr[j + 1] = temp;
            }
        }
    }
}

// ========== O(2^n) — ЭКСПОНЕНЦИАЛЬНАЯ ==========
// Все подмножества (перебор)
void print_subsets(int *arr, int n) {
    int total = 1 << n;  // 2^n подмножеств
    for (int mask = 0; mask < total; mask++) {
        printf("{");
        for (int i = 0; i < n; i++) {
            if (mask & (1 << i)) {
                printf("%d ", arr[i]);
            }
        }
        printf("}\n");
    }
}

int main(void) {
    printf("=== Асимптотическая сложность ===\n\n");
    
    int arr[] = {1, 3, 5, 7, 9, 11, 13, 15};
    int n = 8;
    
    printf("O(1) - доступ: arr[3] = %d\n", get_first(arr));
    printf("O(log n) - бинарный поиск числа 9: позиция %d\n",
           binary_search(arr, n, 9));
    printf("O(n) - линейный поиск числа 9: позиция %d\n",
           linear_search(arr, n, 9));
    printf("O(n) - сумма массива: %lld\n\n", sum_array(arr, n));
    
    int arr2[] = {5, 2, 8, 1, 9, 3};
    printf("До сортировки: ");
    for (int i = 0; i < 6; i++) printf("%d ", arr2[i]);
    
    merge_sort(arr2, 0, 5);
    printf("\nПосле merge_sort O(n log n): ");
    for (int i = 0; i < 6; i++) printf("%d ", arr2[i]);
    printf("\n\n");
    
    printf("O(2^n) - все подмножества {1,2,3}:\n");
    int small[] = {1, 2, 3};
    print_subsets(small, 3);
    
    return 0;
}

/*
Важнейший нижний предел:
  Сортировка сравнениями не может быть быстрее O(n log n)!
  Доказательство через дерево решений: n! листьев → высота ≥ log2(n!) ≥ n log n
  
  Но! Сортировка подсчетом (Counting sort) обходит это:
  O(n + k), где k — диапазон значений
  Это НЕ противоречие — она не основана на сравнениях
*/
```

## Практические правила оценки трудоемкости

Для анализа программ используются правила, основанные на свойствах O-символики.

**Правило 1: Последовательность**
```
T(S₁; S₂) = O(max(f(n), g(n)))
```
Доминирует наиболее тяжелая операция.

**Правило 2: Произведение (вложенные циклы)**
```
T(for i: S) = O(n · g(n))
```
Внешний цикл n раз × сложность тела.

**Правило 3: Ветвление**
```
T(if p then S₁ else S₂) = O(max(f(n), g(n)))
```
В анализе худшего случая берем максимум.

**Правило 4: Константы игнорируются**
```
O(C · f) = O(f)   при C > 0
```

```c
// Практический анализ трудоемкости с комментариями

#include <stdio.h>

// ========== АНАЛИЗ СЛОЖНОСТИ ФРАГМЕНТОВ КОДА ==========

void complexity_examples(int n) {
    printf("=== Анализ трудоемкости ===\n\n");
    
    int sum;
    
    // O(1) — одна операция
    sum = n * (n + 1) / 2;  // Формула Гаусса
    printf("Формула Гаусса: 1+2+...+%d = %d  [O(1)]\n", n, sum);
    
    // O(n) — один цикл
    sum = 0;
    for (int i = 0; i < n; i++) {
        sum += i;  // O(1) внутри
    }
    printf("Сумма циклом: %d  [O(n)]\n\n", sum);
    
    // O(n²) — вложенные циклы
    printf("Таблица умножения %dx%d  [O(n²)]:\n", 3, 3);
    for (int i = 1; i <= 3; i++) {            // n раз
        for (int j = 1; j <= 3; j++) {        // n раз
            printf("%3d", i * j);             // O(1)
        }
        printf("\n");
    }
    printf("\n");
    
    // O(n²) + O(n) = O(n²) — доминирующий член
    sum = 0;
    for (int i = 0; i < n; i++) {             // O(n)
        sum += i;
    }
    for (int i = 0; i < n; i++) {             // O(n²)
        for (int j = 0; j < n; j++) {
            sum += i * j;
        }
    }
    // Итого: O(n) + O(n²) = O(n²)
    printf("Последовательно O(n) + O(n²) = O(n²), sum=%d\n\n", sum);
    
    // O(log n) — деление пополам
    printf("Деление пополам [O(log n)]:\n");
    int val = n;
    int steps = 0;
    while (val > 1) {
        val /= 2;
        steps++;
    }
    printf("  %d → 1 за %d шагов ≈ log2(%d) = %.1f\n\n",
           n, steps, n, log2(n));
    
    // O(n log n) — n итераций с log n каждая
    printf("[O(n log n)] — n элементов × log n бинарных поисков:\n");
    printf("  Это класс оптимальных алгоритмов сортировки\n\n");
}

// ========== КАК АНАЛИЗИРОВАТЬ СЛОЖНОСТЬ РЕКУРСИИ ==========

// Рекуррентное соотношение: T(n) = T(n-1) + O(1)
// Решение: T(n) = O(n) — линейная
int recursive_factorial(int n) {
    if (n <= 1) return 1;        // O(1)
    return n * recursive_factorial(n - 1);  // T(n-1) + O(1)
}

// T(n) = 2·T(n/2) + O(n)
// Мастер-теорема (Cormen): T(n) = O(n log n)
void merge_sort_analysis(int *arr, int left, int right) {
    if (left >= right) return;
    int mid = (left + right) / 2;
    merge_sort_analysis(arr, left, mid);      // T(n/2)
    merge_sort_analysis(arr, mid + 1, right); // T(n/2)
    // merge: O(n)
}

int main(void) {
    complexity_examples(8);
    
    printf("Рекурсивные сложности:\n");
    printf("  factorial(5) = %d  [T(n) = T(n-1)+O(1) → O(n)]\n",
           recursive_factorial(5));
    printf("  merge_sort: T(n) = 2T(n/2)+O(n) → O(n log n)\n");
    printf("  fibonacci(naive): T(n) = T(n-1)+T(n-2) → O(2^n)\n");
    
    return 0;
}

/*
Мастер-теорема (Master Theorem, Cormen et al. 1990):
  Для T(n) = a·T(n/b) + O(n^c):
  
  Если c < log_b(a): T(n) = O(n^log_b(a))
  Если c = log_b(a): T(n) = O(n^c · log n)
  Если c > log_b(a): T(n) = O(n^c)
  
  Примеры:
  - merge sort: a=2, b=2, c=1: c = log₂(2) → O(n log n)
  - binary search: a=1, b=2, c=0: c = log₂(1) = 0 → O(log n)
  - Strassen matrix mult: a=7, b=2, c=2: log₂(7)≈2.81 > 2 → O(n^2.81)
*/
```

## Анализ сложности на примерах

### Сортировка пузырьком — O(n²)

Внутренний цикл: O(1) за сравнение и обмен, но повторяется до n раз. Внешний цикл: n раз. Итого: O(n²).

На очень малых данных (n < 20) пузырьковая сортировка может конкурировать из-за малых константных накладных расходов.

### Числа Фибоначчи — от O(2ⁿ) до O(log n)

```c
#include <stdio.h>
#include <time.h>

// ========== O(2^n) — НАИВНАЯ РЕКУРСИЯ ==========
// Проблема: fib(n) = fib(n-1) + fib(n-2)
// fib(5) вызывает fib(3) ДВАЖДЫ — экспоненциальное дублирование
long long fib_naive(int n) {
    if (n <= 1) return n;
    return fib_naive(n - 1) + fib_naive(n - 2);
}

// ========== O(n) — ИТЕРАТИВНЫЙ ПОДХОД ==========
long long fib_iterative(int n) {
    if (n <= 1) return n;
    long long a = 0, b = 1;
    for (int i = 2; i <= n; i++) {
        long long c = a + b;
        a = b;
        b = c;
    }
    return b;
}

// ========== O(n) — МЕМОИЗАЦИЯ (top-down DP) ==========
#define MAX_N 100
long long memo[MAX_N];

long long fib_memo(int n) {
    if (n <= 1) return n;
    if (memo[n] != -1) return memo[n];
    memo[n] = fib_memo(n - 1) + fib_memo(n - 2);
    return memo[n];
}

// ========== O(log n) — ВОЗВЕДЕНИЕ МАТРИЦЫ В СТЕПЕНЬ ==========
// Использует тождество:
// [F(n+1)]   [1 1]^n   [F(1)]
// [F(n)  ] = [1 0]   × [F(0)]

typedef struct {
    long long m[2][2];
} Matrix;

Matrix matrix_multiply(Matrix A, Matrix B) {
    Matrix C;
    for (int i = 0; i < 2; i++) {
        for (int j = 0; j < 2; j++) {
            C.m[i][j] = 0;
            for (int k = 0; k < 2; k++) {
                C.m[i][j] += A.m[i][k] * B.m[k][j];
            }
        }
    }
    return C;
}

Matrix matrix_power(Matrix M, int n) {
    if (n == 1) return M;
    if (n % 2 == 0) {
        Matrix half = matrix_power(M, n / 2);
        return matrix_multiply(half, half);
    }
    return matrix_multiply(M, matrix_power(M, n - 1));
}

long long fib_logn(int n) {
    if (n <= 1) return n;
    Matrix M = {{{1, 1}, {1, 0}}};
    Matrix result = matrix_power(M, n);
    return result.m[0][1];
}

int main(void) {
    printf("=== Числа Фибоначчи: сравнение алгоритмов ===\n\n");
    
    // Инициализация мемо
    for (int i = 0; i < MAX_N; i++) memo[i] = -1;
    
    int test_values[] = {10, 20, 30};
    
    for (int t = 0; t < 3; t++) {
        int n = test_values[t];
        
        clock_t start, end;
        
        start = clock();
        long long naive = fib_naive(n);
        end = clock();
        double naive_time = (double)(end - start) / CLOCKS_PER_SEC * 1000;
        
        long long iterative = fib_iterative(n);
        long long memoized = fib_memo(n);
        long long logn = fib_logn(n);
        
        printf("F(%d) = %lld\n", n, iterative);
        printf("  Наивная рекурсия:  %.2f мс  [O(2^n)]\n", naive_time);
        printf("  Итеративный:       O(n)   результат %lld\n", iterative);
        printf("  Мемоизация:        O(n)   результат %lld\n", memoized);
        printf("  Матричный (O(logn)):       результат %lld\n\n", logn);
    }
    
    printf("Формула Бине (но имеет проблемы с точностью):\n");
    printf("  F(n) = (φ^n - ψ^n) / √5\n");
    printf("  φ = (1 + √5) / 2 ≈ 1.6180339887...\n");
    printf("  (golden ratio, 'золотое сечение')\n");
    
    return 0;
}

/*
Динамическое программирование (Dynamic Programming, DP):
  - Термин ввел Richard Bellman (1957)
  - Идея: запомнить результаты подзадач, не вычислять дважды
  - Два подхода:
    1. Top-down (мемоизация): рекурсия + кэш
    2. Bottom-up (табуляция): итеративное заполнение таблицы
  
  Применения DP:
  - Числа Фибоначчи, факториал
  - Кратчайший путь (Dijkstra, Bellman-Ford)
  - Задача о рюкзаке
  - Редакционное расстояние (Levenshtein)
  - Выравнивание последовательностей ДНК (Smith-Waterman)
*/
```

## Амортизационный анализ на примере динамического массива

В некоторых случаях асимптотическая оценка «в худшем случае» дает слишком пессимистичный прогноз. **Амортизационный анализ** (Robert Tarjan, 1985) рассматривает среднюю стоимость операции в длинной последовательности действий.

**Стратегия удвоения (doubling strategy):**
- При заполнении массива: выделить в **2 раза больше** памяти и скопировать все элементы
- Отдельная вставка в момент расширения: O(n)
- Но большинство вставок — O(1)

**Доказательство амортизации:**
- Добавим n элементов: 1 + 1 + 1 + ... + 1 + n = n + n = 2n = O(n) суммарно
- Более точно: копирований всего ~n (геометрическая прогрессия: 1 + 2 + 4 + ... + n/2 = n-1)
- Амортизированная стоимость одной вставки: 2n/n = O(1)

```c
#include <stdio.h>
#include <stdlib.h>
#include <string.h>

// ========== ДИНАМИЧЕСКИЙ МАССИВ (ВЕКТОР) ==========

typedef struct {
    int *data;
    int size;      // Текущее количество элементов
    int capacity;  // Выделенная память
    long long total_copies;  // Счетчик операций копирования
} DynamicArray;

DynamicArray* da_create(void) {
    DynamicArray *da = malloc(sizeof(DynamicArray));
    da->data = malloc(sizeof(int) * 1);
    da->size = 0;
    da->capacity = 1;
    da->total_copies = 0;
    return da;
}

void da_push(DynamicArray *da, int value) {
    if (da->size == da->capacity) {
        // Удвоение: O(n) здесь, но редко!
        int new_capacity = da->capacity * 2;
        int *new_data = malloc(sizeof(int) * new_capacity);
        
        // Копирование — вот откуда O(n)
        for (int i = 0; i < da->size; i++) {
            new_data[i] = da->data[i];
            da->total_copies++;
        }
        
        free(da->data);
        da->data = new_data;
        da->capacity = new_capacity;
        
        printf("  [Расширение до capacity=%d, скопировано %d элементов]\n",
               new_capacity, da->size);
    }
    da->data[da->size++] = value;
}

void da_destroy(DynamicArray *da) {
    free(da->data);
    free(da);
}

int main(void) {
    printf("=== Амортизационный анализ: динамический массив ===\n\n");
    
    DynamicArray *da = da_create();
    int n = 20;
    
    printf("Добавляем %d элементов:\n", n);
    for (int i = 1; i <= n; i++) {
        da_push(da, i);
    }
    
    printf("\nИтоги:\n");
    printf("  Добавлено элементов: %d\n", da->size);
    printf("  Итоговая ёмкость:    %d\n", da->capacity);
    printf("  Суммарно копирований: %lld\n", da->total_copies);
    printf("  Копирований ≈ n = %d (%lld операций)\n", n, da->total_copies);
    printf("\n  Амортизированная стоимость одной вставки:\n");
    printf("  Суммарно / n = %lld / %d = %.2f ≈ O(1)\n\n",
           da->total_copies + n, n,
           (double)(da->total_copies + n) / n);
    
    printf("Содержимое: ");
    for (int i = 0; i < da->size; i++) printf("%d ", da->data[i]);
    printf("\n\n");
    
    printf("Доказательство:\n");
    printf("  При добавлении n элементов расширений: log₂(n) = %.0f раз\n",
           log2(n));
    printf("  Копирований: 1 + 2 + 4 + ... + n/2 = n-1 ≈ n\n");
    printf("  Суммарно операций: n (вставки) + n (копирования) = 2n = O(n)\n");
    printf("  Амортизированно: O(n)/n = O(1) на вставку\n");
    
    da_destroy(da);
    return 0;
}

/*
Стратегии расширения динамического массива:
  
  1. Удвоение (×2): амортизированно O(1), но тратит до 2× памяти
  2. Умножение на 1.5: лучший баланс (Python использует ~1.125x)
  3. Прибавление константы: O(n) амортизированно — ПЛОХО!
  
  std::vector (C++): использует удвоение
  Python list: использует ~1.125x
  Java ArrayList: начинает с 10, затем 1.5x
  
  Другие примеры амортизационного анализа:
  - Splay trees (Robert Tarjan, 1985): O(log n) амортизированно
  - Union-Find с path compression: почти O(1) амортизированно
  - Fibonacci heaps: O(1) амортизированно для insert/decrease-key
*/
```

## Практическая эффективность и аппаратные ограничения

Математическая модель сложности часто абстрагируется от аппаратных нюансов. Реальная производительность определяется:

### Иерархия памяти

| Уровень | Размер | Задержка (latency) |
|---------|--------|-------------------|
| Регистры | ~1 KB | 1 такт (~0.3 нс) |
| L1 кэш | 32-64 KB | 4-5 тактов (~1.5 нс) |
| L2 кэш | 256 KB — 1 MB | 12-15 тактов (~5 нс) |
| L3 кэш | 4-64 MB | 30-50 тактов (~15 нс) |
| ОЗУ | ГБ | 100-200 тактов (~60 нс) |
| SSD | ТБ | ~0.1 мс |
| HDD | ТБ | 5-10 мс |

**Разница между L1 и ОЗУ: ~100 раз!** Алгоритм, дружественный кэшу, может быть в 10-20 раз быстрее "оптимального" по O-нотации.

```c
// Демонстрация влияния кэша на производительность

#include <stdio.h>
#include <time.h>
#include <stdlib.h>

#define N 1000

// ROW-MAJOR (по строкам) — кэш-дружественный для C
double row_major_sum(double matrix[N][N]) {
    double sum = 0;
    for (int i = 0; i < N; i++) {
        for (int j = 0; j < N; j++) {
            sum += matrix[i][j];  // Последовательный доступ в памяти
        }
    }
    return sum;
}

// COLUMN-MAJOR (по столбцам) — кэш-враждебный в C
double col_major_sum(double matrix[N][N]) {
    double sum = 0;
    for (int j = 0; j < N; j++) {
        for (int i = 0; i < N; i++) {
            sum += matrix[i][j];  // Доступ с шагом N (cache miss!)
        }
    }
    return sum;
}

// Демонстрация: "random access" vs "sequential access"
void cache_demo(void) {
    int size = 1 << 22;  // 4M элементов = 16 MB
    int *arr = malloc(size * sizeof(int));
    for (int i = 0; i < size; i++) arr[i] = i;
    
    clock_t start, end;
    volatile long long sum = 0;
    
    // ПОСЛЕДОВАТЕЛЬНЫЙ ДОСТУП — кэш работает
    start = clock();
    for (int i = 0; i < size; i++) {
        sum += arr[i];
    }
    end = clock();
    printf("  Последовательный: %.1f мс\n",
           1000.0 * (end - start) / CLOCKS_PER_SEC);
    
    // СЛУЧАЙНЫЙ ДОСТУП — кэш-промахи
    // Создаем случайные индексы
    int *indices = malloc(size * sizeof(int));
    for (int i = 0; i < size; i++) indices[i] = i;
    // Перемешиваем (Fisher-Yates shuffle)
    srand(42);
    for (int i = size - 1; i > 0; i--) {
        int j = rand() % (i + 1);
        int tmp = indices[i]; indices[i] = indices[j]; indices[j] = tmp;
    }
    
    sum = 0;
    start = clock();
    for (int i = 0; i < size; i++) {
        sum += arr[indices[i]];  // Cache miss для каждого обращения!
    }
    end = clock();
    printf("  Случайный доступ:  %.1f мс (в несколько раз медленнее!)\n",
           1000.0 * (end - start) / CLOCKS_PER_SEC);
    
    free(arr);
    free(indices);
}

int main(void) {
    printf("=== Практическая эффективность и кэш ===\n\n");
    
    printf("Cache-friendly vs Cache-hostile обход матрицы:\n");
    printf("(Оба алгоритма O(n²), но реальная скорость различается!)\n\n");
    
    cache_demo();
    
    printf("\nВыводы:\n");
    printf("  - O-нотация игнорирует константы\n");

    printf("  - Блочные алгоритмы (blocked/tiled) для работы с матрицами\n");
    
    return 0;
```

## Типовые ошибки и неверные интерпретации

1. **Смешение сложности и времени**: Оценка O(f(n)) говорит о **скорости роста трудоемкости**, а не о точном времени выполнения в секундах. O(n²) при n=10 может быть быстрее O(n log n) при n=10^6.

2. **Игнорирование констант на малых данных**: На небольших массивах (до нескольких тысяч элементов) алгоритм с худшей асимптотикой может быть быстрее из-за меньшего постоянного коэффициента.
   - Пример: `std::sort` в C++ использует introsort = quicksort + heapsort + **insertion sort** для малых массивов

3. **Вера в «бесплатную» память**: Емкостная сложность так же важна, как вычислительная; нехватка памяти может привести к сбросу данных на диск (свопинг) и катастрофическому падению скорости.

4. **Равновероятность веток в O-анализе**: Асимптотическая оценка часто предполагает худший случай для всех `if`, хотя в реальности некоторые ветки могут почти никогда не выполняться.

5. **Игнорирование амортизации**: "Операция занимает O(n)" — часто это амортизированно O(1). Нельзя применять worst-case к каждому вызову в последовательности.

6. **Неправильный выбор n**: Сложность зависит от того, что мы считаем "n". Для алгоритма на графах это может быть V (вершины), E (рёбра) или оба параметра.

7. **P vs NP**: Отсутствие полиномиального алгоритма для NP-задачи не доказано — может быть, вы просто его не нашли. P = NP? — не доказано (Millennium Problem, Clay Mathematics Institute, $1M).

## Математические основы

### Формализация машины Тьюринга

Машина Тьюринга: M = (Q, Γ, b, Σ, δ, q₀, F), где:
- Q — конечное множество состояний
- Γ — алфавит ленты
- b ∈ Γ — пустой символ
- Σ ⊆ Γ \ {b} — входной алфавит
- δ: (Q \ F) × Γ → Q × Γ × {L, R} — функция перехода
- q₀ — начальное состояние
- F ⊆ Q — допускающие состояния

### Асимптотическая нотация (Bachmann-Landau, введена в CS Knuth 1973)

- **O(f(n))**: ∃c > 0, n₀: ∀n ≥ n₀: T(n) ≤ c · f(n) — «не быстрее»
- **Ω(f(n))**: ∃c > 0, n₀: ∀n ≥ n₀: T(n) ≥ c · f(n) — «не медленнее»
- **Θ(f(n))**: T(n) = O(f(n)) и T(n) = Ω(f(n)) — «точная оценка»
- **o(f(n))**: lim(n→∞) T(n)/f(n) = 0 — «строго быстрее»
- **ω(f(n))**: lim(n→∞) T(n)/f(n) = ∞ — «строго медленнее»

### Правила вычисления трудоемкости

| Конструкция | Правило |
|-------------|---------|
| Последовательность S₁; S₂ | O(max(f, g)) |
| Цикл × тело | O(n · g) |
| if-else | O(max(f, g)) |
| Константа | O(C · f) = O(f) |

### Рекуррентные соотношения и числа Фибоначчи

- Факториал: T(n) = T(n-1) + O(1) → T(n) = O(n)
- Фибоначчи наивно: T(n) = T(n-1) + T(n-2) + O(1) → T(n) = O(φⁿ) ≈ O(2ⁿ)  
  где φ = (1+√5)/2 ≈ 1.618 (золотое сечение)
- Фибоначчи итерация: T(n) = O(n)
- Фибоначчи матрица: T(n) = O(log n)

### Мастер-теорема (Master Theorem, Cormen 1990)

Для T(n) = a·T(n/b) + Θ(n^c), a ≥ 1, b > 1:

- Если c < log_b(a): T(n) = Θ(n^(log_b a))
- Если c = log_b(a): T(n) = Θ(n^c · log n)
- Если c > log_b(a): T(n) = Θ(n^c)

### Амортизационный анализ (Robert Tarjan, 1985)

Для динамического массива с удвоением:
- Суммарно копирований при n вставках: Σᵢ₌₀^(log₂n) 2ⁱ = 2n - 1 < 2n
- Суммарно операций (вставки + копирования): n + 2n = 3n = O(n)
- Амортизированная стоимость: O(n)/n = O(1)

### Нижние оценки для сортировки

Любой алгоритм сортировки, основанный на **сравнениях**, требует Ω(n log n) сравнений:
- n! возможных перестановок → log₂(n!) ≥ n log n - n/ln2 (формула Стирлинга)
- Дерево решений высоты ≥ log₂(n!)

## Вопросы для собеседования

1. **В чем заключается принципиальное различие между «задачей сортировки» и «алгоритмом сортировки»?**
   Задача — "упорядочить элементы" — может иметь множество алгоритмов-решений (пузырек, merge sort, quicksort, counting sort), различающихся по сложности, памяти и константам.

2. **Откуда произошло слово "алгоритм"?**
   От латинизированного имени арабского математика Мухаммада аль-Хорезми (Muhammad ibn Musa al-Khwārizmī, ~820 н.э.). А.А. Марков предложил альтернативный термин "алгорифм" для подчеркивания связи с арифметикой.

3. **Кто написал первую программу в истории?**
   Ada Lovelace (1843) — алгоритм вычисления чисел Бернулли для Аналитической машины Бэббиджа.

4. **Перечислите четыре фундаментальных свойства, которыми должно обладать предписание, чтобы считаться алгоритмом.**
   Конечная запись, завершаемость (за конечное число шагов), универсальность (применимость к классу данных), правильность (решает задачу, а не просто завершается).

5. **Что утверждает тезис Чёрча-Тьюринга и почему он является именно тезисом, а не теоремой?**
   Утверждает, что любая функция, интуитивно вычислимая, реализуема на МТ. Тезис, а не теорема — потому что связывает формальное понятие (МТ) с интуитивным ("вычислимость"), которое нельзя формально определить и, следовательно, доказать.

6. **Кто и когда создал машину Тьюринга и машину Поста?**
   Alan Turing (1936), "On Computable Numbers" — МТ. Emil Post (1936) — машина Поста, независимо и одновременно.

7. **Что такое проблема остановки и почему она неразрешима?**
   Halting Problem: нет алгоритма, определяющего для ЛЮБОЙ программы P и входа x, завершится ли P(x). Доказано Тьюрингом (1936) через диагонализацию — предположение о существовании такого алгоритма приводит к противоречию.

8. **Какая формальная модель вычислений (Тьюринга или Поста) более близка к архитектуре современных императивных программ и почему?**
   Машина Поста — она хранит "метку текущего оператора" и переходит между пронумерованными командами, что ближе к счетчику команд (PC) и инструкциям современного процессора.

9. **Что именно измеряет асимптотическая сложность O(f(n)) и какие факторы она намеренно игнорирует?**
   Скорость роста числа операций при n→∞. Игнорирует: константные множители, слагаемые меньшего порядка, константную составляющую, аппаратные особенности (кэш, частоту процессора).

10. **Кто ввел O-нотацию в CS?**
    Donald Knuth (1973) — стандартизировал для CS. Оригинально: Paul Bachmann (1894) и Edmund Landau (1909) в математике.

11. **Почему алгоритм с худшей асимптотикой (например, O(n²)) может оказаться эффективнее на малых наборах данных?**
    Из-за меньшего константного множителя. Пример: std::sort использует insertion sort для массивов из <16 элементов, несмотря на O(n²), из-за минимальных накладных расходов.

12. **Как вычисляется общая сложность программы, состоящей из двух последовательно выполняемых блоков с разным порядком роста?**
    T = O(max(f(n), g(n))). Пример: O(n²) + O(n log n) = O(n²).

13. **В чем причина экспоненциальной сложности наивного рекурсивного вычисления чисел Фибоначчи?**
    Многократное вычисление одних и тех же подзадач. fib(n-2) вычисляется при вызове fib(n) и при вызове fib(n-1). Дерево вызовов растет как 2ⁿ.

14. **Как решить эту проблему? Какие подходы и каковы их сложности?**
    Мемоизация (top-down DP): O(n); итерация (bottom-up DP): O(n); матричное возведение в степень: O(log n); формула Бине: O(log n) но проблемы с точностью (числа с плавающей точкой).

15. **Что такое динамическое программирование и кто его придумал?**
    DP (Richard Bellman, 1957) — техника запоминания результатов подзадач. Два подхода: мемоизация (top-down) и табуляция (bottom-up).

16. **В чем заключается основная идея амортизационного анализа на примере динамического массива?**
    Единичная "тяжелая" операция (удвоение при копировании, O(n)) встречается редко, большинство вставок O(1). Суммарно n вставок = O(n) операций → амортизированно O(1) на каждую.

17. **Почему амортизированная стоимость вставки в динамический массив считается константной O(1)?**
    Геометрическая прогрессия копирований: 1+2+4+...+n/2 = n-1. Вместе с n вставками: 2n-1 операций. Делим на n вставок: ≈2 = O(1).

18. **Что такое Мастер-теорема?**
    Метод решения рекуррентных соотношений вида T(n) = a·T(n/b) + Θ(n^c). Сформулирована в "Introduction to Algorithms" (Cormen, Leiserson, Rivest, 1990).

19. **Как иерархия памяти (кэши против ОЗУ) влияет на константный множитель в реальной сложности алгоритма?**
    Cache miss: ~100x медленнее cache hit. Алгоритм с хорошей локальностью данных может быть в 10-20 раз быстрее "оптимального" по O-нотации, игнорирующего кэш.

20. **Что понимается под «экономической эффективностью» алгоритма в индустриальном программировании?**
    Баланс между: скоростью выполнения, расходом памяти, стоимостью разработки и сопровождения, простотой реализации, масштабируемостью. Иногда O(n²) выгоднее O(n log n) при малом n.

21. **Что такое NP-полнота?**
    Класс задач, для которых не найдено полиномиального алгоритма. Если решение угадано, его можно проверить за полиномиальное время. Примеры: SAT (Cook, 1971), TSP, Knapsack. P vs NP — открытая проблема ($1M, Millennium Problem).

22. **Можно ли вычислить точное смещение поля в структуре, если оно представлено в виде битового поля (bit field)?**
    Нет. Стандарт C не определяет порядок бит внутри слова для битовых полей, их упаковку и выравнивание. Оператор `offsetof` запрещен для битовых полей.

## Итоги и следующие шаги

- Понятие алгоритма требует строгой формализации для возможности научного рассуждения о свойствах программ.
- **История**: аль-Хорезми (~820), Евклид (~300 до н.э.), Ada Lovelace (1843), Turing/Church/Post (1936).
- Различные формальные модели вычислений (МТ, Поста, λ-исчисление, алгорифмы Маркова) эквивалентны по вычислительным возможностям.
- Фундаментальные требования: конечная запись, завершаемость, универсальность, правильность.
- Асимптотический анализ (Knuth, 1973) фокусируется на скорости роста ресурсов, игнорируя константы.
- Правила: T(S₁;S₂) = max, T(for×body) = произведение, T(if) = max веток.
- Рекурсивные решения могут приводить к O(2ⁿ) — мемоизация (DP) снижает до O(n), матричный метод до O(log n).
- Амортизационный анализ (Tarjan, 1985) даёт реалистичную оценку для последовательностей операций: динамический массив O(1) амортизированно.
- Реальная производительность сильно зависит от иерархии памяти: cache miss в 100× медленнее hit.
- Выбор алгоритма — баланс между математической оптимальностью, аппаратными ограничениями и стоимостью разработки.
